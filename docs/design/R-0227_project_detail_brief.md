## Brief

- Primary User: 晴樹さん（建具店の経営者・見積担当）。PC の広い画面で使う
- Job: 1つの案件について、得意先・状態・日付・予定（現調/見積/製作/取付など）・見積と売上の伝票を一度に見て、直す
- 主要操作: 予定の入力（日付・時間・メモ）、ステータス・納期の変更、伝票を開く、保存
- 成功条件: スクロールせずに主要情報（基本情報・予定・伝票一覧）が一画面に入る。予定の表に横スクロールが出ず、時間・メモが読める。触れる場所がひと目で分かる

## 事実（今の画面、`frontend/src/pages/ProjectDetail.tsx`）

- 画面全体が `max-w-2xl`（672px）の1列。カード（`bg-white rounded-lg shadow-sm p-5`）を縦に積む: 基本情報 → 画像 → 予定（`ProjectSchedulesPanel.tsx`）→ 見積伝票 → 売上伝票 → 作業時間（見積合計）→ 能力チェック（`CapacityCheckPanel`）→ … → 危険な操作
- 基本情報の欄: 案件コード、案件名、得意先、ステータス（ボタン群）、受注日、納品日、納期、工数目安（h）、施主、元請、連絡先、施工住所、備考
- 入力欄はすべて角丸・個別の枠・欄の間に gap-4

## 共通の UI ルール（全案共通。R-0184 の決まりを土台にする）

1. 角丸をやめる（入力欄・ボタン・カードとも 0〜2px）
2. 隣り合う欄は枠線を共有し、間に余白を置かない（意味のまとまりを1つの枠で囲み、中は1px線で区切る）
3. 触れるものはすべて、マウスが乗ったときに枠と背景が変わる（例: 枠を濃い青に、背景を薄い青に）。触れないもの（表示だけの値）は変わらない。フォーカス時は青い枠
4. 高密度: 文字 12〜13px、入力欄の高さ 22〜24px、行の間は1px線、カード内の余白は 8px 程度。見出しは小さく1回だけ
5. 数値・金額は右寄せ・3桁区切り・等幅数字。金額は ¥
6. 予定の表は横スクロールなし。時間の欄は「12.5」が読める幅
7. 色は今の Beaver のまま（slate 系の文字、青のアクセント、白地）

## 比べる構造の案（見本で2〜3案）

- 案A: 2列。左に基本情報（ラベル左・値右の詰めた表）、右に予定と伝票
- 案B: 上に案件の要点の帯（コード・名前・得意先・ステータス・納期を1〜2行）、その下に予定を全幅、さらに下を2列（詳細情報｜伝票）
- 案C（任意）: 案A/B と違う考え方があれば1つ

いずれも同じデータ（実在の案件1件、予定5行程度、見積2件・売上1件）・同じ画面幅（1440px と 1280px で崩れない）で描く

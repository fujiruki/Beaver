# R-0230 伝票編集 実寸見本 v3（D案）注記

対象: `R-0230_voucher_edit_mock.html` / `frontend/src/styles/voucherEdit.css`

## 左右切替の条件

- 明細の最小幅 1,283px、右サマリー 286px、間隔 8px、画面内側の左右余白 16px、明細パネルの左右罫線 2pxを合計し、**見本のコンテンツ幅が 1,595px 以上**の時だけ左右配置にする。
- 1,595px未満では、詳細サマリーをヘッダーの下・利益率操作の上に横長で置く。したがって見本の 1,920px は右、1,440px・1,280pxは上になる。ブラウザ幅ではなく `.ve-page` の実幅をコンテナクエリで判定する。
- 右サマリーはトップバーの下で `sticky`。表示領域を越える場合はサマリー内を縦スクロールできる。狭い画面のサマリーは固定せず、トップバーと競合させない。
- 明細は 1,283px を最小幅とし、広い時は明細枠いっぱいに伸ばす。左右余白は各8pxで、1,440pxでは横スクロールなし、1,280pxでは `.ve-lines-scroll` の中だけ横スクロールする。ページ全体を横にはみ出させない。

## v3 で変えた点

- 画面内側の左右余白を各8pxにし、明細を最小1,283px・利用可能幅いっぱいに変更した。1,440pxでは明細全体を表示し、1,280pxだけ明細内横スクロールを許す。
- 通常行の品名横に「製品台帳／台帳を直す」とメニューボタンを追加した。値引・小計行には出さない。これは v1/v2 で意図的に省略したものではなく、既存機能の反映漏れだった。
- 利益率の早押しと適用対象表示の隣に「原価から売値を設定」を追加した。これも v1/v2 で意図的に省略したものではなく、既存機能の反映漏れだった。
- 説明・非表示記録と明細の複数行入力はサイズ変更を禁止した。ヘッダー欄は `field-sizing: content` で入力に応じて伸び、非表示記録も全文を編集・確認できる。未対応ブラウザでは2行分を最小高とし、実装時は入力イベントによる自動伸長で同じ動作を補う。
- 入力値を共通の本文サイズに、重要な明細列見出しを一段上の見出しサイズに合わせた。実装構造を説明する注記は本番想定の見本内から外した。

## DESIGN_SYSTEM への適合確認

- `beaver-ui.css` を先に、画面固有の `voucherEdit.css` を後に相対パスで読み込んだ。React実装でも同じ2ファイルを使用できる。
- 外枠を `.bv-ui` に限定し、`bv-panel`、`bv-cell`、`bv-control`、`bv-btn`、`bv-toggle`、保存状態、数値クラスを再利用した。共通部品の追加は不要と判断したため、`beaver-ui.css` と `ui-kit.html` は変更していない。
- 角丸を加えず、隣接セルは罫線を共有する。入力欄は白、見出し・表示専用領域は沈んだ背景とした。
- 金額・時間は右寄せ、3桁区切り、等幅数字。金額は `¥`、時間は `h` を付けた。
- 原価・作業帯は橙、売値帯は緑とし、入力順に原価・作業→売値→行利益の順で並べた。売値内訳は明細に残し、サマリーには混ぜていない。
- 重要なエラーだけ赤を使い、通常の保存済み表示は控えめにした。操作可能な要素は既存 `bv-` のホバー規則に従う。

## 計算の確認結果

見本は各明細の入力値からJavaScriptで毎回集計し、サマリー・詳細集計を同じ結果から描画する。既存 `voucherCalc.ts` に合わせ、通常行を原価・時間の対象とし、値引行は売上・利益・粗利から差し引く。小計行は表示専用で再集計しない。売値合計は `calcLineSellTotal` と同じく、数量×単価の浮動小数点誤差を小数第6位で丸めてから円未満を切り捨てる。消費税も既存計算どおり切り捨てる。

初期状態（通常2行＋値引＋小計、税抜入力）の照合結果:

| 項目 | 結果 | 根拠 |
|---|---:|---|
| 通常行の売値 | ¥390,000 | ¥230,000 + ¥160,000 |
| 値引 | -¥20,000 | 値引行 |
| 課税対象額（税抜） | ¥370,000 | ¥390,000 - ¥20,000 |
| 消費税 | ¥37,000 | floor(¥370,000 × 10%) |
| 売上（税込） | ¥407,000 | ¥370,000 + ¥37,000 |
| 本体原価 | ¥160,000 | 2×¥45,000 + ¥70,000 |
| 金物原価 | ¥28,000 | 2×¥8,000 + ¥12,000 |
| ガラス原価 | ¥32,000 | 2×¥7,000 + ¥18,000 |
| 労務費 | ¥66,500 | (11h + 8h) × ¥3,500/h |
| 製造原価 | ¥286,500 | 材料¥220,000 + 労務¥66,500 |
| 利益 | ¥83,500 | 値引後売上¥370,000 - 製造原価¥286,500 |
| 利益率 | 22.6% | ¥83,500 ÷ 税抜伝票合計¥370,000 |
| 工場時間 | 14h | 2×4h + 6h |
| 現場時間 | 5h | 2×1.5h + 2h |
| 合計時間 | 19h | 14h + 5h |
| 粗利 | ¥150,000 | 値引後売上¥370,000 - 材料¥220,000 |
| 粗利率 | 40.5% | ¥150,000 ÷ ¥370,000 |
| 日割り粗利 | ¥63,158/日 | ¥150,000 ÷ (19h ÷ 8h)、表示時に四捨五入 |

税込入力時は `floor(税込課税額 × 0.1 ÷ 1.1)` で内税を求め、税込総額から内税を引いた値を利益率の分母にする。時間区分が増減しても `measure_type === 'time'` の全区分を数量倍して合計するため、工場・現場以外を追加した場合も「合計時間」には含まれる。ただし大項目の「工場時間」「現場時間」は該当コードだけを表示する想定である。

# R-0200 伝票明細から製品台帳を作る・直す

## 1. Primary Job

見積明細を書いている流れを切らずに、複雑な製品の材料・金物・工程を積み上げ、その原価を選択中の明細へ確実に反映する。

## 2. 明細から開く入口

品名欄の右に、既存の台帳アイコンを置き換える「製品台帳」ボタンを置く。未紐付け時は押すと小メニューで「新しく作る」「台帳から選ぶ」、紐付け済みなら主操作を「台帳を直す」、隣の▼に「別の台帳を選ぶ」「紐付けを外す」とする。

選択行の直上に一括操作を増やさない。どの明細を対象にするかが品名との近さだけで分かり、1行ずつ書く手順に合うため。

## 3. 編集面（推す案／比較案）

### 推す案 A: 大型モーダル

伝票の上に、画面幅の約 90%（最大 1180px）、高さ約 86vh のモーダルを出す。背後の選択明細は薄く見えるが操作不可。上部に「見積 E03988・明細5」を固定表示し、編集対象を見失わせない。入力中に伝票の金額を見比べる必要はなく、保存後に同じ明細へ戻ればよい。

現在の `TateguItemDetail` の基本情報、材料費明細、労務費明細と集計ロジックを再利用し、モーダル用に一画面へ圧縮する。左に品番・製品名・仕様・単位、中央に材料・金物の原価行、下に工程行、右に固定集計を置く。既存ページへ遷移させない。

### 比較案 B: 右引き出し

幅 720px の引き出しを右から出し、左側に伝票を残す。対象の見比べには強いが、材料・工程の表が窮屈で横スクロールまたは縦長カード化が必要になる。工程が多い状態ほど往復が増えるため不採用。

## 4. 保存と明細への反映

主ボタンは「保存して明細へ反映」。保存成功後にモーダルを閉じ、対象行を選択したまま次をスナップショットとして上書きする。

- 原価: 本体・金物・ガラスの区分別金額
- 作業: 工場時間・現場時間
- 労務単価（台帳工程が複数単価なら、明細で同じ労務費になる換算単価）
- 製造原価: 上記から再計算した合計
- 台帳ID・製品名（紐付け表示用）

反映後は対象行に「製品台帳 05707から反映」と一時表示し、次の主操作を既存 `ProfitRateBar` の「原価から売値を設定」にする。売値は自動変更しない。

既存台帳の編集時は、モーダル上部に「この保存は製品台帳を更新し、この伝票の明細5だけに原価を反映します」と常時表示する。他伝票の明細は保存済みスナップショットを維持し、変えない。確認ダイアログは重ねない。

## 5. 名前

画面表示は「製品台帳」でよい。建具以外も対象にしたい意図と一致する。ルート名・型名など内部実装の改名や Access との用語統一は別件とする。

## 6. 情報の優先順位・状態

優先順位は、(1) 編集対象と製品名、(2) 製造原価・区分合計・工数、(3) 材料／金物と工程の入力行、(4) 仕様・単位・備考、(5) 補助操作。色がなくても、固定見出し・罫線・桁揃え・余白でこの順を保つ。

状態は以下を設計対象とする。

| 状態 | 見せ方／動作 |
|---|---|
| 新規作成 | 製品名へ初期フォーカス。明細品名を初期値にし、品番は「保存時に採番」 |
| 既存を直す | 台帳番号と更新対象を上部に固定表示 |
| 他伝票でも使用 | 「他の伝票は変わりません」を上部に明記。追加確認はしない |
| 原価0 | 集計を `¥0` と表示し、保存ボタン近くに「原価が0円です」。保存自体は許可 |
| 工程が多い | 工程表だけ内部スクロール。見出しと右の集計は固定 |
| 保存失敗 | モーダルを閉じず、入力を保持。上部に失敗理由と「もう一度保存」 |

確認には見積 E03988（住吉産業）、製品台帳 05707「トイレブース扉 開き勝手交換」、製造原価 ¥36,200（本体 ¥0／金物 ¥6,500／ガラス ¥0／労務 ¥29,700）、工数 9h、材料行「作業」1、運搬・経費 05320 ¥27,100 を使用した。

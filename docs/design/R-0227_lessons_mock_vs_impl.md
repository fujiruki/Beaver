# R-0227 見本（HTML/CSS）と実装がずれた理由と、デザイン手順書（good-design）への提案

- 2026-10-30 記録。R-0227 がうまくいったら、この内容をデザイン手順書担当の AI に伝えて手順書を改良してもらう（晴樹さんの指示）
- 経緯: 案D の見本を見て構造を決めた → 仕様に「見本の CSS を Tailwind で再現」と書いて Codex に実装させた → テストは通ったが、指揮役が画面を見ずに「beta に入れた、見て」と報告 → 晴樹さんに「実際にみて見比べましたか？」と言われ、見本と beta を並べたら大きくずれていた

## 見本と実物の違い（2026-10-30、1568px 幅で比較）

- 入力欄: 見本は枠を共有した表のマスに直接書き込む形。実物はマスの中にさらに枠付きの入力欄があり、枠が二重で間に余白もある（晴樹さんが嫌だと言った形そのもの）
- 要点の並び: 見本はコード・案件名・得意先・ステータス・納期が1行。実物は4〜5段
- 説明の欄: 見本は4行、実物は1行
- 作業時間: 見本は項目名付き、実物は項目名がなく数字が右端に離れる
- 基本情報: 見本は左に項目名・右に値の詰まった表。実物は項目名が上で枠付きの欄を2列
- 予定の表の見出し: 実物は「時間」と「メモ」がくっつき、見出しと列がずれる
- 見本で見えない問題: 日付を「20261105」と続けて打つと年の欄に「202611」が入る（`max` が無いので年が4桁で次へ進まない）。時間の「12.5」が数値の上下の矢印に隠れる

## ずれた理由

1. 見本のコードを使わず「Tailwind で再現」と訳し直させた。実装側は既存の部品（項目名が上の欄・枠付きの入力欄）を並べ替えるだけで済ませた
2. 見本が最終決定より古いまま。済の位置・工程名・作業時間の置き場は文章で足しただけで、見た目の正がどこにも無かった
3. テストは並び順や欄の有無だけを確かめ、見た目（枠の二重・余白・見出しのずれ）は確かめない
4. 最後に誰も画面を見なかった（指揮役の手落ち）
5. 見本が実際の状態（空の行・薄い字の行・入力途中・実データ）を描いていなかった

## デザイン手順書への提案

1. 引き渡しの前に見本を最終決定に合わせて直し、それを正とする（文章の補足で済ませない）。見本に版の名前を付けて固定する
2. 見本の HTML/CSS をそのまま移す。まず見本の構造と CSS を部品へ移し、そのあとデータをつなぐ。「CSS を再現する」のような訳し直しの指示をしない
3. 見た目の受け入れ確認を手順に入れる。同じデータ・同じ画面幅で見本と実物の画面写真を並べ、違いを一覧にし、0件か晴樹さんが認めるまで完了にしない。写真は実装側が添え、まとめ役が自分の目で見る
4. 操作の確認表: マウスを乗せる・フォーカス・日付を続けて打つ・Tab で移動・保存を、実際のブラウザで1回ずつ試す
5. 見本に実際の状態（空・入力途中・長い文字・0件）を描き、DB の実データを使う
6. 見本の画面写真（実データ・実寸）をチャッピー（ChatGPT）にも見せて、余白の無駄・まとまりの崩れ・触れるか分からない部品を指摘してもらう工程を入れる（晴樹さんの提案、2026-10-30）。v2 の見本でも、晴樹さんが見て初めて「工数目安が打てるように見えない」「得意先の情報が散らばっている」「説明の上に無駄な余白」が見つかった。AI が自分で作った見本を自分で確かめるだけでは見落とす
7. 業務ツールの見た目の原則として「入力すべき場所を目立たせるのではなく、それ以外の場所を目立たなくする」を手順書に入れる（晴樹さん、2026-10-30）。R-0227 では入力欄を白のまま、パネルの見出し・列見出し・項目名・表示だけの値を一段沈んだ灰色にして、視線が入力欄に集まるようにした。見出しを太くする・色を付けるなど「足して目立たせる」方向の提案（チャッピーも出した）は、業務ツールでは採らない

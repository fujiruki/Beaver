# R-0197 伝票詳細モーダル UI設計

## 1. Primary Job

右の伝票がどの案件に入るものかを、得意先・摘要・明細の内容から見分ける。

## 2. 情報の優先順位と表示内容

- **Primary**: 伝票番号＋種別、得意先、摘要、合計金額、明細（品名・取付場所・数量・単価・金額・備考）
- **Secondary**: 伝票日付、状態、備考、税抜金額・消費税
- **Supporting**: 「伝票画面で開く」
- **Metadata**: 明細件数（例: `4件`）。内部ID・同期元・更新日時・原価・利益率は出さない

並びは、`伝票番号・種別・状態 → 日付・得意先 → 摘要 → 明細 → 備考 → 金額`。明細は初期表示で最大8行、9行以上は明細領域だけをスクロールし、見出しを固定する。件数は省略しない。

`VoucherEdit?readonly=1` の埋め込みではなく専用の軽い表示を推す。既存画面は原価・利益・同期・編集可否など割り当て判断に不要な情報が多く、横幅も大きい。専用表示なら判断に必要な項目を1画面に収め、モーダルを閉じた後のドラッグ操作へ戻りやすい。完全情報が必要な時だけ「伝票画面で開く」で既存画面へ遷移する。

## 3. 状態と操作

### 状態

- 読込中: 見出し枠を保ち、本文に3本のスケルトン。閉じる操作は可能
- 明細0件: 明細表内に「明細はありません」。ヘッダーと合計は表示
- 明細が多い: 8行分（約320px）で内部スクロール、列見出し固定、「全12件」を表示
- void: 見出し横に枠線の `取消`、本文上部に「取消済みの伝票です」。金額は残す
- 請求済み: 見出し横に `請求済み`。警告にはせず、内容確認を妨げない（案件変更可能なため）
- 読込失敗: 本文に短いエラーと「再試行」。既に一覧で見えている番号・種別は見出しに残す

### ドラッグ、ダブルクリック、キーボード

- カード全体をドラッグ対象、ダブルクリックで詳細を開く。`pointerdown` の位置から4pxを超えて動いたらドラッグ扱いとし、その操作系列のダブルクリックを抑止する
- カードは `tabindex="0"` 相当。`Enter` で開く。ドラッグできない利用者向けの割り当て操作は本要望では増やさず、別途検討する
- 閉じ方は `Esc`、薄暗い外側のクリック、右上の `×`。モーダル内部クリックでは閉じない。閉じたら開いたカードへフォーカスを戻す
- 「伝票画面で開く」はフッター左の控えめなリンク。現在タブで開き、戻り先に `/projects?assign=1` を保持する
- モーダル内に「割り当て」は置かない。案件選択UIを重複させず、閉じてカードをドラッグする一貫した流れにする

視線は **Entry**（番号・種別・状態）→ **Handoff**（得意先・摘要）→ **Reading**（明細を左から右、金額列へ）→ **Return**（合計、閉じる、元カード）の順。色を外しても、文字サイズ・罫線・余白・右揃えだけで階層が分かる構造にする。

## 4. 大きさ・位置

PC前提で中央配置、幅 `min(960px, calc(100vw - 64px))`、最大高さ `calc(100vh - 64px)`。背景は黒24%で、左右の一覧の位置関係は見えるが操作はさせない。案件名を読み比べながら詳細を開き続ける要件ではないため、案件一覧の文字まで常時読める必要はない。閉じるとスクロール位置と検索条件を維持する。

## 5. 2案比較と推奨

| | A. 軽量モーダル（推奨） | B. 右ドロワー |
|---|---|---|
| 判断速度 | 明細幅を確保し、数量・単価・金額を横に比較しやすい | 案件一覧は残るが明細が狭く折り返す |
| 現在位置 | 背景とフォーカス復帰で保つ | 左一覧を常時読める |
| 操作競合 | 開いている間はドラッグ不可で明確 | カード列を覆い、カード切替とドラッグの境界が曖昧 |
| 適性 | 1伝票を短時間で精査 | 複数案件と長時間見比べる用途 |

推奨は **A**。今回のPrimary Jobは案件の選択そのものではなく、まず伝票の所属を見分けること。960pxの表で明細を読み、閉じて元カードをそのままドラッグする二段階が最も誤操作が少ない。

## 実データ確認

- 売上 `S08468`（徳山建設、摘要「只様邸 マグネットラッチ部材」、¥1,100、明細1行）: 余白過多にならず、要点と合計が一視野に収まる
- 見積 `E03988`（住吉産業、明細4行、備考65文字）: 4行と備考・合計までスクロールせず読める。長い備考は全文を2〜3行で表示する

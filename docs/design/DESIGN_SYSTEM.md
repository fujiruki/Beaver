# Beaver のデザインの決まり

- 2026-11-02 作成（R-0229）。もとになった画面: 案件詳細（R-0227、見本 `R-0227_project_detail_mock_v2.html`）と伝票の明細（R-0184）
- **画面を作る・直すときは、このファイルを読んでから good-design（v1.6）で進める**
- 色・大きさの数字の正本は CSS（`frontend/src/styles/beaver-ui.css` の `--bv-*`）。このファイルには数字を書き写さない
- 部品の見た目の正本は見本帳 `docs/design/ui-kit.html`（同じ CSS を読む）

## 1. 原則

1. **業務ツールなので、情報は画面にぎゅっと詰める。** 余白で区切らず、罫線・背景・列見出しで区切る。縦スクロールはしてよい（一画面に収めることを目的にしない）
2. **入力すべき場所を目立たせるのではなく、それ以外の場所を目立たなくする。** 入力欄は白。見出し・列見出し・項目名・表示だけの値を一段沈んだ色にして、視線が入力欄に集まるようにする。見出しを太くする・色を付ける、など「足して目立たせる」ことはしない。例外として、消す操作・保存の失敗・納期の超過は目立たせる
3. **角丸にしない。**
4. **隣り合うものは枠線を共有し、間に余白を空けない。** 意味のまとまりを1つの枠で囲み、中は1px線で区切る。入力欄はマスそのもの（マスの中にさらに枠付きの欄を置かない）
5. **触れるものは、マウスを乗せたら枠と背景が青系に変わる。触れないもの（表示だけの値）は変わらない。** 触れるかどうかを、押して初めて分かる作りにしない
6. **数値・金額は右寄せ・3桁区切り・等幅数字。金額は ¥。**
7. **文字の濃さは3段。** 入力した値・主な情報／見出し・項目名／未入力の薄い字

## 2. 部品（共通。クラス名は `bv-`）

| 部品 | 使うところ | クラス |
|:--|:--|:--|
| 画面の枠 | 新しい決まりで作った画面の一番外側。中だけに決まりが効く（古い画面に影響させない） | `bv-ui` |
| パネルと見出し | 画面の中のまとまり。見出しは沈んだ色・小さい文字。右にボタンを置ける | `bv-panel` `bv-panel-title` `bv-panel-actions` `bv-panel-note` |
| マス（項目名＋値） | 項目名が上、値が下の入力・表示 | `bv-cell` `bv-label` `bv-value` `bv-readonly` |
| 入力欄 | マスそのものとして見える入力。単独で置くときも同じ | `bv-control` `bv-edit-cell` |
| 項目名が左の表 | 基本情報のような、項目名と値の2列 | `bv-info` `bv-info-label` `bv-info-value` |
| 表 | 一覧・明細。列見出しは沈んだ色。行全体を押せるなら `bv-row-click` | `bv-table` `bv-row-click` |
| まだ作っていない行・追加の行 | 決まった行を薄い字で並べる、末尾の「＋ 追加」 | `bv-placeholder-row` `bv-add-row` |
| 空の欄の薄い字 | 空の日付欄（`bv-empty-date`）・空のメモ | `bv-empty-date` |
| ボタン・リンク | ふだんは控えめ、乗せると青。主な操作は `bv-btn-primary`、消すのは赤 | `bv-btn` `bv-btn-primary` `bv-btn-danger` `bv-link` `bv-link-danger` |
| 切り替えボタンの並び | ステータスなど。選んでいるものだけ青 | `bv-toggle-list` `bv-toggle` `bv-toggle-active` |
| 上に固定する帯と保存の状態 | 自動保存の画面。「保存済」は灰色、保存中は青、失敗は赤で消えない | `bv-topbar` `bv-save-saved` `bv-save-saving` `bv-save-error` |
| 元に戻すの案内 | 左下。変更のたびに「〇〇を変更しました［元に戻す］」 | `UndoToast`（`bv-undo`） |
| 数値・金額 | 右寄せ・等幅 | `bv-number` `bv-amount` `bv-mono` |
| 期限の色 | 近い（橙）・超過（赤） | `bv-due-soon` `bv-due-over` |
| 危険な操作 | 画面の一番下、赤の見出し | `bv-danger` |

画面だけで使う並べ方（列の比率・その画面だけのマスの並びなど）は、その画面の CSS（例 `projectDetail.css`、`pd-`）に書く。2つ以上の画面で同じ形が出てきたら、`bv-` に移す。画面の中で共通部品を真似して作り直さない。

## 3. 動き

- **自動保存**: 保存ボタンを置かない。文字の欄は欄を出たとき、選ぶもの・押すものは決めた時点で保存。変わった項目だけ送る。古い保存の応答で上書きしない。保存の状態を上の帯に出す
- **元に戻す**: 保存が成功するたびに「〇〇を変更しました［元に戻す］」。押すと前の値を保存し直す。行を作った・消したも元に戻せる
- **フォーム**: 自動保存の画面ではフォームのネイティブ送信を起こさない（`onSubmit` で止める・ボタンはすべて `type="button"`）
- **表の行**: 入力中に行を並べ替えない。決まった行（薄い字）は、行から出たときに保存。保存が終わるまで入力した値を消さない。保存待ちのあいだに二重に作らない
- **日付の欄**: `max="9999-12-31"`（年を4桁で次へ進ませる）
- **数値の欄**: 上下の矢印を出さない（値が隠れる）

## 4. やってはいけないこと（実際に起きた失敗）

- 見本を「Tailwind で再現」のように訳し直して実装する → 見本と別物になった（R-0227）。見本の HTML の構造とクラス名をそのまま使う
- テストが通ったことだけで完了と報告する → 見た目のずれと、「元に戻す」でページが再読み込みされる不具合を見逃した（R-0227）。見本と実物を並べて見比べ、ブラウザで操作して確かめる
- 部品を画面ごとに書く（`inputCls` が4ファイルに別々にあった）

## 5. 新しい画面・直す画面の進め方

1. このファイルと見本帳を読む
2. good-design（v1.6）で進める。主な業務の画面・保存や元に戻すのある画面は L3
3. 見本は見本帳と同じ CSS を読んで描き、実データを使う。足りない部品は `bv-` に足して見本帳にも載せる
4. 実装は見本の構造とクラス名をそのまま使う
5. beta で見本と並べて見比べ、操作して確かめてから晴樹さんに見せる

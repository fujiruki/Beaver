# R-0225: 予定の表で入力中に行が動かないようにする／メモ欄を広げる

- 状態: 本番反映済み（2026-10-30）。ブラウザでの確認は未
- 要望の原文: `docs/requests_log.md` の R-0225
- 関係する仕様: R-0220、R-0222、R-0224
- 対象: `frontend/src/components/ProjectSchedulesPanel.tsx`（案件の画面の予定の表）のみ。API の並び順・段取りの画面・やること一覧は変えない

## 原因

1. 薄い字の行（決まった種類でまだ無いもの）は表の先頭にまとめて描き、保存済みの行は API の日付順で描いている。薄い字の行の日付を入れた瞬間（`onChange`）に保存され、その行は保存済みの行の中の日付順の位置へ移る。入力中のほかの欄はそこで消える
2. 保存済みの行も日付を変えると取り直しで並び直し、行が上下に動く
3. 日付の入力は年を1桁打つたびに `onChange` が走り、途中の年（0002年など）で保存されることがある
4. メモの列だけ幅の指定が無く、ほかの列（w-32・w-40・w-40・w-24・w-12・w-12）に押されて細くなる

## 仕様

- **並び順を入力で変えない**。表の行は次の順に固定する
  1. 決まった種類（`FIXED_SCHEDULE_KINDS`：現調・見積・製作・取付）の順に、その種類の保存済みの行（id 順）。1件も無ければ同じ位置に薄い字の行
  2. それ以外の種類の保存済みの行（id 順）。種類を変えた行もここでは id 順の位置にとどまる（種類の変更で決まった種類の枠へ飛ばさない。取り直し後の並びは「その行の今の種類」で決めてよいが、編集中に動かないこと＝次項）
  3. 末尾の空の行
- **編集中は動かさない**: 表の中に入力中の欄（フォーカス）がある間は、取り直したデータで行の並びを変えない。フォーカスが表から出たときに上の順で並べ直す（並び順を state に持ち、フォーカスが表の外へ出たら作り直す、など）
- **薄い字の行・末尾の空の行は、行からフォーカスが出たときに保存する**（`<tr>` の `onBlur` で `relatedTarget` が同じ行の外のとき）。欄ごとの `onChange` では保存しない。保存する条件（日付か時間のどれかが入っている）は今のまま
- 保存した薄い字の行は、同じ位置に保存済みの行として出る（上の並び順により自然にそうなる）
- **メモの列を広げる**: メモの入力欄に最小幅（目安 12rem）を付ける。日付の列は日付が読める範囲で狭めてよい。画面が狭いときは表を横にスクロールさせる（表を `overflow-x-auto` の箱で包む）

## 受け入れ条件（vitest、Testing Library）

1. 薄い字の「見積」の行で開始日を入れても、行は保存されず、フォーカスが同じ行の時間の欄へ移っても値が残る。行の外へフォーカスを出すと1回だけ作成の API が呼ばれる
2. 保存済みの行の日付を変えて、取り直したデータの日付順が変わっても、フォーカスが表の中にある間は行の順が変わらない
3. 表の行の順が「現調・見積・製作・取付（薄い字含む）→ ほかの種類 → 空の行」になる
4. 回帰スイートが全部通る

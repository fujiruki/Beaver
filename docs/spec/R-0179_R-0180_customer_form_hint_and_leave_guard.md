# R-0179・R-0180・R-0176不具合修正: 得意先の新規登録画面の改善（S4での要望）

- 受付: 2026-10-16 藤田晴樹さんがBeaver_betaの受入確認（S4）で要望（dodai-back経由）。似た得意先の候補表示（R-0176）は「すばらしい」とのこと
- 状態: 仕様確定

## R-0179: 似た得意先の候補があることを入力欄の近くで知らせる

背景: 候補（R-0176）は画面の下のほうにしか出ないため、得意先名を入力している間は気づけない。

1. 候補が1件以上あるとき、名前・カナ・電話の入力欄の近く（得意先名の入力欄のすぐ下）に、短い案内「似た得意先が{件数}件あります（画面下を確認）」を出す
2. 案内を押すと、候補の一覧の位置へスクロールする（`scrollIntoView`、滑らかに）
3. 候補が0件になったら案内も消す。候補の一覧そのもの（R-0176）は今の位置・内容のまま
4. 対象はR-0176と同じ2か所: 得意先の新規登録画面（`CustomerDetail.tsx`の新規モード）と、案件画面の新規得意先モーダル（`NewCustomerModal.tsx`）。候補の取得は1回にまとめ、案内と一覧で同じ結果を使う（二重に呼ばない）

## R-0180: 得意先画面の未保存表示と、離れるときの確認

背景: 入力の途中で、保存せずにタブや画面を閉じられてしまう。

対象: 得意先詳細画面（`CustomerDetail.tsx`）の新規登録と編集の両方。案件画面のモーダルは対象外。

1. フォームに未保存の変更があるとき（react-hook-formの`isDirty`。新規は何か入力したら）、画面の右下に固定で「未保存の変更があります」を表示する。伝票画面のR-0172の保存状態表示と同じ見た目・位置にそろえる（右下固定）。保存ボタンは今の位置（一番下）のまま
2. 未保存の変更があるときに:
   - タブを閉じる・再読み込みする → ブラウザの確認（`beforeunload`）
   - 画面内で別の画面へ移る（メニュー・戻るボタン・ブラウザの戻る）→ 確認ダイアログ「保存していない入力があります。このページを離れますか？」（React Routerの`useBlocker`。伝票画面の実装にそろえる）
3. 保存に成功して画面を移るとき、R-0176の候補を選んで既存の得意先へ移るとき、R-0167の「再読み込み」のときは確認を出さない
4. 保存に失敗したとき（R-0167の409を含む）は未保存のまま表示を続ける

## R-0176 不具合修正: 既存側の名前・カナが2文字未満なら照合しない

背景: 候補に「165 田中住建（カナ: ﾀ）一致: カナ」が出た。登録済みの得意先のカナが1文字（ﾀ）で、それが入力したカナに含まれるだけで一致になっていた。

1. 名前・カナの照合で、入力側だけでなく既存の得意先側も、正規化した後に2文字未満なら照合しない（`api/routes/customers.php`の`/customers/similar`）
2. 電話の照合（6桁未満は照合しない）も、既存側に同じ下限を当てる

## 受け入れ条件（テスト）

PHP:

1. 既存の得意先のカナが「ﾀ」、名前が1文字のとき、入力「タナカジュウケン」「田中住建」で候補に出ない
2. 既存側の電話が5桁以下なら、電話では一致しない
3. R-0176の既存テストが通る

vitest:

4. 候補があると、得意先名の入力欄の近くに「似た得意先が{件数}件あります（画面下を確認）」が出る。押すと候補の一覧へスクロールする（`scrollIntoView`が呼ばれる）。候補が0件なら出ない
5. 候補の取得APIは、案内と一覧で1回しか呼ばれない
6. 新規登録で入力すると右下に「未保存の変更があります」が出る。保存に成功すると消える
7. 未保存のまま画面内の別の画面へ移ろうとすると確認が出る。キャンセルすると移らず、OKすると移る
8. 未保存のときは`beforeunload`で確認が出る（`preventDefault`が呼ばれる）。未保存でなければ出ない
9. 保存に成功して移るとき・候補を選んで移るときは、確認が出ない
10. 既存のテストと回帰スイートが通る

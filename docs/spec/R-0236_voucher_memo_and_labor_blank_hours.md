# R-0236 伝票の「説明」欄 ／ R-0237 労務費の空の行の工数を空にする

## R-0236 伝票の画面に「説明」の欄を出す

確かめた今の作り: `vouchers.memo` の列があり、`PUT /vouchers/{id}` も `memo` を受け付ける。Dodaikun の用語集では Access の伝票の「説明」が `vouchers.memo` に当たる。伝票の画面（`VoucherHeader.tsx`）には欄が無い。「摘要」は `description` で別物。

1. 伝票のヘッダーに「説明」の欄を足す。複数行（初めは2行、書くと伸びる。案件詳細 R-0227 の説明欄と同じ作り）。摘要の下の行に置く。
2. 保存は今のヘッダーと同じ（編集は欄から出たときに自動保存、新規は保存ボタン）。
3. 読み取り専用の伝票では表示だけ。
4. 印刷（プレビュー）にも説明を出す。見積書に載るため。空なら出さない。
5. Access との同期で説明（memo）を送り合うかは dodai-back に確かめる。Beaver 側の同期の窓口と DB は今回変えない。
6. R-0230 の見本にも説明の欄を足す。

受け入れ条件: 説明を書いて欄から出ると `PUT` に `memo` が入る。読み取り専用で入力できない。印刷の表示に説明が出る。

## R-0237 製品台帳の労務費の空の行で、工数を空にしておく

対象: `frontend/src/components/TateguLineItemsPanel.tsx` の労務費の空の行（`LaborBlankRow` と、Tab で行を加える処理）

1. 労務費の空の行の工数は、いつも空で出す（今は 1）。
2. 空の行に何か入れたかの判定は「工程名・工数・単価のどれかが入ったか」にする（今は工数が 1 以外かで判定している）。
3. 工数を空のまま行を加えたら、工数は 0 で保存する。
4. 材料費の空の行の数量（1）は今回変えない。

受け入れ条件: 工場時間・現場時間の空の行の工数の欄が空。工程名だけ入れて行から出ると、工数 0 の行が1つ加わる。何も入れずに行から出ても行は加わらない。

## R-0236 追記（2026-11-02、dodai-back の調べと Beaver の窓口の確認）

- Access の伝票の「説明」は `vouchers.memo`。見積書の説明欄もこれ（空なら「この度はご相談ありがとうございます。」）。Access は今、伝票ヘッダーの memo を送っておらず、取り込みもしていない。
- Beaver の同期の窓口を確かめた結果:
  - **受け取り**（`sync_helpers.php` の伝票の upsert）は `memo = excluded.memo` で、Access が memo を送らないと **null で上書きする**。このままだと Beaver で書いた説明が、Access が伝票を送り直すたびに消える。
  - **返す側**（`VOUCHER_SYNC_SELECT_COLUMNS`）に `v.memo` が入っていない。
- そのため Beaver 側で次の2つを直す（上の 5 を改める）:
  1. 受け取りで `memo` のキーが無いときは、今の値を残す（キーがあれば、その値で更新。null を送ってきたら空にする）。
  2. 返す列に `v.memo` を足す。
- 同期の窓口を変えるので、本番に入れる時期は dodai-back と合わせる。Access 側の送る・取り込む直しは dodai-back の担当。両方向で同期するかは dodai-back が晴樹さんに確かめる。

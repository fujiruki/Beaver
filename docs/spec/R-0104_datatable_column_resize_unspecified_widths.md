# R-0104: 列幅ドラッグでまだ他列の幅が変わる（R-0103の追加修正）

## 背景
R-0080フィードバック（id=17, id=18, 2026-08-06 23:47/23:58）より。R-0103（`minWidth:100%`除去）を本番デプロイした後も、得意先列をドラッグで縮めると開始日・納期など他列の幅が変わってしまうという再報告。

> はい、得意先列を縮めてみたのがこのスクショです。そしたら、得意先列は縮んだけど、開始日や納期の幅が大きくなっていませんか？私の希望は、得意先の幅が縮んだら、その右のステータス・開始日、納期、操作、工数目安の列は幅はそのままで左に寄って、工数目安列の右が余白になってほしい。もちろんそのときに得意先列より左にある案件コード、案件名の列の幅も変化しない。

## 根本原因
`frontend/src/pages/ProjectList.tsx`の列定義は`actions`列以外（`project_code`/`name`/`customer_name`/`status`/`start_date`/`delivery_date`/`effective_estimated_hours`）に`width`が未指定。

`frontend/src/components/DataTable.tsx`の`colgroup`部分（315〜317行目付近）:
```tsx
const w = widths[col.key] ?? col.width;
return <col key={col.key} style={w !== undefined ? { width: `${w}px` } : undefined} />;
```
`widths[col.key]`（ユーザーがドラッグして保存した幅）も`col.width`（列定義のデフォルト幅）も無い列は、`<col>`に幅指定が一切出ない。

テーブルは`table-layout: fixed`のため、幅指定のある列はその幅で固定されるが、**幅指定のない列同士は、テーブル全体の幅から幅指定列の合計を引いた残り幅を、初期描画時の内容幅の比率で自動配分**する。得意先列をドラッグして`widths['customer_name']`に明示幅がセットされると、それまで「幅指定なし」グループの一員だった得意先列がグループから抜け、残った「幅指定なし」グループ（開始日・納期等）の中で再配分が起きる（＝相対的に幅が広がって見える）。

R-0103（`minWidth:100%`除去）はテーブル全体の伸縮は直したが、この「幅指定のない列同士が伸縮を吸収し合う」問題自体は解消していなかった。

## 修正方針
DataTableコンポーネント内で、**初回描画後（マウント後）に、まだ明示幅を持たない列の実測幅（レンダリング結果の実ピクセル幅）を測定し、それを暗黙のデフォルト幅として`widths`ステートに書き込んで固定する**。

- 対象: `widths[col.key]`も`col.width`も未定義の列
- 測定方法: 各`<th>`に`ref`を張り、`useLayoutEffect`（`tableId`が変わった＝マウント時のみ、依存配列は`[tableId]`）で`getBoundingClientRect().width`を読み取る
- 測定結果は`setWidth()`経由で`widths`ステートに反映するが、**`persist()`は呼ばない**（localStorageには保存しない＝ユーザーが明示的にドラッグ操作するまでは自動測定値であり、次回訪問時やcolumns定義変更時は再測定させたいため）
- これにより、初回描画時点で全列が明示px幅を持つ状態になり、以降どの列をドラッグしても、他の列の`<col>`幅は変化しなくなる（table-layout:fixedが素直に各列固定幅を守る）

### 影響範囲の確認
`useColumnWidths`フックに`widths`一括更新用の内部処理を追加する必要がある（`setWidth`は1キーずつの更新だが、複数列を一度に測定して反映する際にレンダリング回数が増えすぎないよう、可能なら1回の`setWidths`でまとめて反映する）。

既存の`widths`/`persist`のAPIシグネチャ（`useColumnWidths`の戻り値）は変更しない（他画面のDataTable利用箇プレイスへの影響を避ける）。测定・反映はDataTable内部で完結させる。

## 確認してほしいこと
- 得意先列（`width`未指定）をドラッグで縮める → 案件コード・案件名（左側）と、ステータス・開始日・納期・工数目安・操作（右側）の幅が一切変化せず、右側の列群が左へ詰まり、テーブル全体の幅が縮む。表の右側（工数目安 or 操作列の右）に余白ができる
- 逆に得意先列を広げた場合も同様（他列は不変、総幅が増える）
- 初期表示（未ドラッグ状態）の見た目が既存と大きく変わらないこと（自動測定は初期描画時の内容幅をそのまま固定するだけなので、視覚的な変化は無いはず）
- 列幅・列順序の既存永続化（localStorage）が壊れないこと。既にlocalStorageに幅が保存されている列はその値を尊重し、自動測定で上書きしないこと
- 他の一覧画面（得意先・建具台帳・伝票・請求書）でも同様の現象が起きうるか確認する（DataTable共通コンポーネントのため、修正は自動的に全画面へ波及する見込み。個別ページの列定義変更は不要）

## TDD必須
`DataTable.test.tsx`（無ければ作成）に以下を検証するテストを追加する:
- `width`未指定の列が複数ある状態で、いずれか1列をドラッグでリサイズしたとき、他の`width`未指定列の`<col>`幅（style width）が変化しないこと
- 自動測定された幅がlocalStorageへ`persist`されないこと（ドラッグして離すまでは保存されない）
- 既存の列幅リサイズ・列順序保存のテストが壊れないこと

jsdom環境では`getBoundingClientRect()`が常に0を返すため、テストでは`Element.prototype.getBoundingClientRect`をモックして実測値を模擬する必要がある（既存のR-0103関連テストで同種の対応があれば参考にする）。

## 受け入れ条件
1. `width`未指定の列を含むテーブルで、ある列をドラッグで縮めても、他の列（左右問わず）の幅は変化しない
2. テーブル全体の幅は、ドラッグした列の幅変化分だけ増減する
3. 初期表示の見た目（各列の幅）が本修正前とほぼ変わらない
4. 列幅・列順序のlocalStorage永続化の既存動作が壊れない
5. 既存のDataTable関連テスト・回帰スイートが通る

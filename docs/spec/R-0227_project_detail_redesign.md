# R-0227: 案件詳細の画面のリデザイン

- 状態: 仕様化済み（2026-10-30）
- 要望の原文: `docs/requests_log.md` の R-0227（3回分）
- デザインの経緯: `docs/design/R-0227_project_detail_brief.md`、見本 `docs/design/R-0227_project_detail_mock.html` の**案D**（`docs/design/R-0227_project_detail.md`）
- 対象: `frontend/src/pages/ProjectDetail.tsx`（既存の案件の編集画面。新規登録の画面は今の1列のまま）、`frontend/src/components/ProjectSchedulesPanel.tsx`、案件詳細の中に出す `CapacityCheckPanel.tsx`。API・DB は変えない

## 構造（案D）

- 画面の幅の上限 `max-w-2xl` をやめ、2列にする（目安: 左 `minmax(0,1.6fr)`・右 `minmax(320px,1fr)`、幅 1100px 未満では1列に積む）
- **左列**（上から）
  1. **案件の要点**: 案件コード（表示のみ）、案件名、得意先、ステータス、納期、**作業時間（見積合計）**（工場・現場の時間。今の「作業時間（見積合計）」カードの中身をここへ移す）、**説明**（今の「備考」`memo` のテキストエリア。4行、縦に広げられる。ラベルは「説明」）
  2. **予定**（`ProjectSchedulesPanel`）
  3. **見積伝票**・**売上伝票**
- **右列**: 基本情報（受注日・納品日・工数目安・施主・元請・連絡先・施工住所。要点に出したものと備考は外す）、画像、能力チェック、ほか今ある欄
- 危険な操作は左右の下、画面の一番下
- **一画面に収めることは求めない**。縦スクロールでよい。左右の下端がそろわなくてよい
- 今ある欄・機能（保存・キャンセル・得意先の新規作成と編集・画像の追加と削除・伝票の作成と開く・Youkan で見る・完全削除など）は1つも落とさない

## 共通の UI ルール（この画面の中のすべての部品）

1. 角丸をやめる（入力欄・セレクト・ボタン・カード。`rounded-*` を外すか `rounded-none`）
2. 隣り合う欄は枠線を共有し、間に余白を置かない。意味のまとまりを1つの枠で囲み、中は1px線（#d8dde3）で区切る
3. 触れるもの（入力欄・セレクト・ボタン・チェックボックス・リンク・クリックできる行）は、マウスが乗ったら枠を青（#2563eb 程度）、背景を薄い青（#eff6ff 程度）にする。フォーカス時も青い枠。触れないもの（表示だけの値）は変わらない。削除だけは赤
4. 高密度: 文字 12〜13px、入力欄の高さ 24px 程度、カードの内側の余白 8px 程度、カードの影はやめて1px線で囲む。見出しは小さく1回だけ
5. 数値・金額は右寄せ・3桁区切り・等幅数字。金額は ¥
6. 色は今の Beaver のまま
- 見本の CSS（`R-0227_project_detail_mock.html`）を正とし、Tailwind のクラスで再現する。共通のクラス文字列は `ProjectDetail.tsx` 内の定数にまとめ、`ProjectSchedulesPanel.tsx` も同じ見た目にする（ほかの画面への展開は別の要望）

## 予定の表

- 列の順: **済**（チェックボックス）→ 種類 → 開始 → 終了/期限 → 時間 → メモ → 削除。横スクロールなし
- 種類が「その他」の行は、種類のセルに「その他」と書かず、**工程名だけ**を出す。工程名の欄（プレースホルダ「工程名」）を種類のセルに置き、その右に種類を変えるための小さなセレクト（▼）を付ける。工程名が空なら「その他」とプレースホルダで見える
- 末尾の「＋ 予定を追加（種類を選ぶ）」の行は今のまま（晴樹さん「使いやすそう」）
- R-0225・R-0226 の動き（入力中は行を動かさない、行から出たときに保存、種類未選択では保存しない）は変えない

## 受け入れ条件（vitest、Testing Library）

1. 既存の案件では、左列に「案件の要点」「予定」「見積伝票」「売上伝票」がこの順に、右列に「基本情報」「画像」がある（data-testid などで列と順を確かめる）
2. 要点に「説明」のテキストエリアがあり、`memo` の値が入っていて、書き換えて保存すると `memo` として送られる。右列の基本情報に備考の欄が無い
3. 要点に作業時間（見積合計）が出る
4. 予定の表の最初の列が「済」のチェックボックス。「その他」の行の種類のセルに「その他」の文字が無く、工程名の入力欄がある
5. 既存のテスト（ProjectDetail・ProjectSchedulesPanel 関連）と回帰スイートが全部通る。構造が変わって既存テストを直すときは、確かめている内容を弱めない

## 構造（見本 v4 のとおり）

- 上に固定した帯（`.pd-topbar`）: ← 戻る・「案件 編集」・保存の状態。アプリ全体のナビの下に固定する
- 左列: 案件の要点 → 予定 → 見積伝票 → 売上伝票。右列（380px）: 基本情報 → 画像 → Youkan。一番下に危険な操作
- 案件の要点
  - 1行目: 案件コード（表示だけ・マス全体灰色）・案件名・得意先（選択）・納期（`title="ここまでに納品したい日"`）＋「あと N 営業日」
  - 得意先の行（表示だけ）: 住所・電話（tel:）・携帯（tel:）・メール（あれば mailto:）・得意先の備考・「得意先を編集」「＋ 新規得意先」（今の動きのまま）
  - ステータス（項目名は左、マスタの全部を並べる）
  - 工数（下記）
  - 説明（`memo`。2行から、書くと伸びる）
- 基本情報: 受注日・納品日（`title="本当に納品した日・納品する日"`）・施主・元請・連絡先・施工住所
- 画像: 0件なら「画像なし（0件）」の1行。追加・拡大・削除は今の動きのまま
- Youkan: 見出しの右に「判定する」（判定済みなら「再判定」）と「Youkan で見る ↗」。中身は「能力チェック: …」の1行。未判定は灰色
- 見積伝票・売上伝票: 行全体を押すと伝票を開く（Enter でも）。マウスを乗せると薄い青
- 今ある機能（得意先の新規作成・編集、画像、伝票の作成と開く、Youkan、完全削除など）は1つも落とさない

## 納期の営業日

- `frontend/src/lib/dandoriCalc.ts` に、今日から納期までの営業日（土日を除く）を数える関数を足す（テストを書く）
- 納期の横に「あと N 営業日」。5営業日以内は `.pd-due-soon`（橙）。今日は「今日」。過ぎたら納期を赤字にし「N 営業日超過」（`.pd-due-over`）。納期が空なら何も出さない

## 自動保存と元に戻す

- 保存ボタンをなくす（上と下の両方）。すべての項目を自動保存にする
  - 文字の欄（案件名・施主・元請・連絡先・施工住所・説明・工数目安）: 欄を出たときに保存（値が変わっていれば）
  - 選ぶもの・押すもの（得意先・ステータス・日付・早押しボタン）: 決めた時点で保存
  - 送るのは変わった項目だけ（`PUT /projects/{id}` に部分で送る。今の API が部分更新を受けるか確かめ、受けないなら今の値を全部送る）
- 保存の状態を上の帯の右に: 平常時「保存済」（灰色）、保存中「保存中…」（青）、失敗「保存できませんでした［再試行］」（赤、消えずに残る）
- 古い保存の応答で画面を上書きしない（項目ごとに最後に送った値だけを正とする）
- 元に戻す: 保存が成功するたびに、左下に「〇〇を変更しました［元に戻す］」（`UndoToast` を使い回す。位置・見た目は見本の `.pd-undo` に合わせてよい）。押すと前の値を保存し直す。案内は8秒で消え、次の変更が来たら置き換わる
- 予定の表の変更（作る・直す・消す）にも同じ案内を出す。元に戻すで、作ったものは消す・直したものは前の値に戻す・消したものは作り直す
- 画面を離れるとき、保存中なら完了を待つ（伝票の R-0168 と同じ考え方）。必須（案件名・得意先）が空のときは保存せず、欄を赤くする

## 予定の表（見本どおり。R-0225・R-0226 の動きは変えない）

- 列: 済・種類・開始・終了/期限・時間(h)・メモ・（削除）。「削除」の列見出しは空
- 薄い字の行は種類名だけ薄く（#94a3b8）、済と削除は無い
- 空の日付欄は `pd-empty-date` クラスを付け、空のメモ欄とともに字を薄く。マウスを乗せるか入力中は普通の濃さ
- 日付の input には `max="9999-12-31"`
- 「その他」の行は種類のマスに工程名だけ＋小さな ▼

## 追加（2026-10-31）: 予定の薄い字の行・空の行で、保存のあいだ値が一瞬消える

- 原因: `ProjectSchedulesPanel.tsx` の `commitFixed`・`commitBlank` が、保存を送る前に下書きを空にしている。保存した予定は `invalidateSchedules` → 取り直しのあとに出るので、そのあいだ行が空になる
- 直し方: 下書きは保存が成功するまで残す（失敗したら残したまま）。作成の `onSuccess` で、返ってきた予定を取り直しを待たずにキャッシュへ足す（`setQueryData`）。取り直しは今どおり
- 受け入れ条件（vitest）: 薄い字の行の時間に 1 を入れて行を出たあと、保存の応答が返るまでのあいだも、その行に 1 が見えている。保存が失敗したら 1 が残る
- 直した（2d1c631・0a8e115）。下書きは保存が成功するまで残し、返ってきた予定をすぐキャッシュに足す。保存待ちのあいだに行から出直しても二重に作らない。残る制限: 応答待ち（ふつう1秒未満）のあいだに値を変えると、その変更は反映されない
- beta で確かめた（2026-10-31）: 取付の薄い字の行の時間に 1 を入れて欄を出ると、保存の前後 31 回（50ms ごと）とも 1 が見えたまま。試しに作った予定は消した（晴樹さんが試した見積 1h・現調 3h はそのまま）

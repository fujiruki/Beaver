# R-0195: 案件一覧の「伝票の割り当て」モード（案件なしの伝票をドラッグで案件に入れる）

- 依頼: 2026-10-24 藤田晴樹さん（このセッションで直接）
  - 「beaverに案件に紐づいてない伝票一覽をだして、ドラッグドロップで案件に適用するみたいな機能が欲しいな　左に案件一覽がでてて、案件新規登録のモーダルが開くボタンもあって、右は案件ひも付きなしの伝票一覽になってるやつ、日付降順になっててほしいな」
  - 「新しく画面をつくるより、、、どうしたらいいかな」→3案から選んで「案件一覽にてそのモードになると右パネルがでるのがいいね、　それぞれに得意先と案件名、適用はでててほしいな　その状態から案件追加をして戻ってもそのモードのままであってほしい」
- 状態: 仕様確定
- 解釈: 「適用」は「摘要」。左の案件には得意先と案件名、右の伝票には得意先と摘要を出す

## 画面

- 案件一覧（`ProjectList.tsx`）に「伝票の割り当て」ボタンを足す。押すとこのモードになり、もう一度押す（または「終了」）と元に戻る
- モード中は画面を左右に分ける
  - 左: 今の案件一覧（検索・並べ替え・「＋新規登録」はそのまま使える）。各行に得意先と案件名が見える
  - 右: 案件に紐づいていない伝票の一覧（voidは除く）。伝票日付の新しい順。各行に伝票日付・伝票番号・種別（見積／売上）・得意先・摘要・金額。見積／売上／両方の切り替えと、得意先・摘要・伝票番号の検索。50件ずつ読み込み（「もっと見る」）
- 右の伝票の行を左の案件の行へドラッグして落とすと、その伝票の`project_id`をその案件にする（`PUT /vouchers/{id}`）。成功したら右の一覧から消え、「元に戻す」付きのお知らせ（既存のUndoToast）を出す。「元に戻す」で`project_id`をnullに戻す
- 伝票の得意先と案件の得意先が違うときは、落としたときに確認する（「得意先が違います（伝票: ○○ ／ 案件: △△）。この案件に入れますか」）。キャンセルなら何もしない
- モードはURLのクエリ（例: `?assign=1`）で持つ。「＋新規登録」で案件を作って案件一覧に戻ったときも、このモードのまま開く（戻り先のURLにクエリを残す。ブラウザの戻るでも同じ）
- 伝票の得意先が未設定のときは、確認なしで入れる

## API

- 伝票一覧（`GET /vouchers`）に、案件なしだけに絞る指定（例: `no_project=1`）を足す。voidは除く。並びは伝票日付の新しい順（同じ日はidの大きい順）。応答に得意先名と摘要を含める（今の一覧の応答に無ければ足す）
- 割り当ては既存の`PUT /vouchers/{id}`の`project_id`で行う（楽観ロックなど既存の扱いに従う）。新しい書き込みAPIは作らない
- 同期: `project_id`の変更で`updated_at`が進むので、Accessは次のプルで受け取る（今の仕組みのまま）

## 受け入れ条件（テスト）

1. `GET /vouchers?no_project=1`は、案件なし・voidでない伝票だけを、伝票日付の新しい順で返し、得意先名と摘要を含む
2. 案件一覧で「伝票の割り当て」を押すと右に案件なしの伝票が出て、URLに`assign=1`が付く
3. 伝票の行を案件の行に落とすと`PUT /vouchers/{id}`が`project_id`付きで呼ばれ、右の一覧から消え、「元に戻す」でnullに戻すPUTが呼ばれる
4. 得意先が違うときは確認が出て、キャンセルならPUTしない
5. `?assign=1`付きで案件一覧を開くとモードで開く（新規登録から戻ったときを含む）
6. 見積／売上の切り替えと検索で右の一覧が絞られる

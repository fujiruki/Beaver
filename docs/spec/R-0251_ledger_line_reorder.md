# R-0251 製品台帳の材料・工程の行を上下に入れ替えて保存する

原文と dodai-back の答えは requests_log の R-0251。晴樹さんの答え（2026-11-10）: **A**（労務費を Access と同じ「1行に工場時間と現場時間」の形にして、順番を Access と同期する）。

## 今の作り（変えないところ）
- DB: `tategu_item_cost_lines` と `tategu_item_labor_lines` は `sort_order` を持つ。保存（PUT /tategu-items/{id}、同期の PUT・POST）は行の配列を全件入れ替え、`sort_order` は送られた値、無ければ配列の順。
- 同期の返り値（`tateguSyncRow`）は `SELECT *` なので `sort_order` を返している。
- 労務費の DB の形は今のまま: 1作業を `FACTORY_TIME` と `SITE_TIME` の2行で持つ（0時間の側は作らない）。DB・migration・同期の窓口は変えない。

## 1. 労務費の表を「1作業1行」にする（画面だけ）
- 列: 工程名・工場時間・現場時間・労務単価・金額（金額は 単価×(工場＋現場)、表示だけ円に四捨五入）。R-0234 の区分の列と区分ごとの空の行はやめ、表の最後に空の行を1行（材料費と同じ流れ。Tab の動きは R-0232 と同じ考え方）。
- 読むとき: `sort_order` 順に見て、隣り合う「同じ工程名・同じ労務単価」の FACTORY_TIME と SITE_TIME を1行にまとめる。相手のいない行は、もう片方を0時間として1行にする。FACTORY_TIME・SITE_TIME 以外の区分の行は、今は作らない前提（あれば今の形で表の下に残して壊さない）。
- 書くとき: 画面の k 行目（1始まり）を、工場時間が0でなければ FACTORY_TIME（sort_order 2k-1）、現場時間が0でなければ SITE_TIME（sort_order 2k）にする。両方0の行も、工程名があれば FACTORY_TIME 0時間で残す（工程を消さないため）。
- これで「同じ作業の工場と現場が離れる」並びは画面で作れなくなる（dodai-back の頼み）。

## 2. 行の並べ替え ▲▼
- 材料費: 各行に ▲▼。並べ替えられるのは同じ区分（本体・金物・ガラス）の中だけ（Access は区分ごとに別の表）。
- 労務費: 各行に ▲▼。1行（工場＋現場）ごと動く。
- 押したら、今の保存の流れ（自動保存がある画面は自動保存、無ければ保存ボタン）で全件を `sort_order` 付きで保存する。保存で台帳の `updated_at` が進み、Access に届く。
- Access から来た wood_calc の行（直せない行）は ▲▼ を出さない。
- 製品台帳の画面と、伝票から開く製品台帳（同じ部品 `TateguLineItemsPanel`）の両方。

## 受け入れ条件
- 読み: [工場A, 現場A, 工場B] → 画面2行（A: 工場・現場、B: 工場のみ）。[現場X] → 1行（工場0）。
- 書き: 上の画面を保存すると sort_order 1,2,3（A工場, A現場, B工場）。B を ▲ で上げて保存 → B工場 1、A工場 3、A現場 4。
- 材料費の ▲▼ は区分の中だけで動き、保存後に開き直しても順番が残る（本物の SQLite の PHP テストで、保存→読み直し）。
- 同期の返り値に、並べ替え後の sort_order が出る。
- ブラウザで: ▲▼ で並べ替え→開き直して順番が残る。

# R-0083: 検索の複数プロパティ対応（Phase 1: 得意先 + ComboSelect共通化）

## 背景

R-0080で届いた本番フィードバック（2026-08-05、`GET /admin/feedback` id=3）より。

> 得意先に限らず多くの検索は、キーワードを名前だけじゃなく読み・電話番号・住所・備考などのプロパティも対象に検索できるようにしてほしい。検索結果が1件に絞られた状態でEnterを押したら、その1件がクリックされた動作にしてほしい。

指揮役からの確認への回答（2026-08-05）:
- 検索対象拡張は「得意先を選ぶ場所すべて」が対象。かつ将来的には得意先に限らず、検索全般で複数プロパティを検索対象に選べる汎用モジュールとして作り、既定は全プロパティを対象にする方針にしたい
- Enterで1件に絞られたら選択扱いにする動作は「検索モジュールを適用したものは全部」が対象

## スコープ（今回のPhase 1）

「汎用モジュール化」という大きな方向性のうち、今回は根拠となった具体的な要望（得意先検索）と、既に複数画面で共有されている `ComboSelect` コンポーネントへの適用に限定する。他の一覧画面（案件、建具台帳、伝票、請求書等）への横展開はPhase 2として別途 `R-0084`（バックログ）に切り出し、今回は行わない。

### 1. `ComboSelect.tsx` の Enter選択修正（共通コンポーネント、全利用箇所に自動的に効く）

現状 `handleKeyDown`（`frontend/src/components/ComboSelect.tsx:64-79`）は、`highlighted >= 0`（矢印キーでハイライトした状態）でないとEnterで選択できない。`filtered.length === 1` の場合は、ハイライトの有無に関わらずEnterでその1件を選択できるようにする。

このコンポーネントは得意先選択・建具選択（`TateguSelector.tsx`）・カタログ品目選択（`CatalogItemSelector.tsx`）で共有されているため、この修正だけで「検索モジュールを適用したもの全部」のEnter選択要望のうち、ComboSelect経由の箇所すべてに効く。

### 2. 得意先検索対象プロパティの拡張

#### バックエンド（`api/routes/customers.php`）

一覧検索（`WHERE ... (name LIKE ? OR code LIKE ?)` 部分、67-84行目付近）を、`name` / `name_kana` / `tel` / `mobile` / `address1` / `address2` / `memo` を対象に拡張する。将来の他エンティティへの再利用を見据え、複数カラムに対する `LIKE` 検索条件を組み立てる小さなヘルパー関数（例: `buildMultiColumnSearchClause(array $columns, string $keyword): array{string, array}`）を作り、customers.php はそれを使う形にする。

#### フロントエンド

- 得意先選択の `ComboSelect` へ渡している `searchText`（得意先名などを結合してComboSelectへ渡している呼び出し元）に、読み・電話番号・住所・備考を連結して含める
- `CustomerList.tsx` の検索ボックスで、検索結果が1件に絞られた状態でEnterを押すと、その得意先の詳細画面へ遷移する（一覧行をクリックした場合と同じ遷移）

### 受け入れ条件

1. `ComboSelect` で検索語により候補が1件に絞られた状態でEnterを押すと、ハイライト操作なしにその1件が選択される（既存の複数候補時の矢印キー選択動作は変更しない）
2. 得意先一覧・得意先系ComboSelectで、名前以外に読み・電話番号・住所・備考のいずれかにマッチする語でも検索でヒットする
3. `CustomerList.tsx` で検索結果が1件のときEnterを押すと詳細画面へ遷移する
4. 既存の得意先検索・一覧のテスト（IME入力・ページネーション等）が壊れないこと
5. PHPテスト・vitestに新規ケースを追加して検証すること

## Phase 2（今回は実施しない・バックログ）

- 同じ複数プロパティ検索パターンを、案件一覧・建具台帳一覧・伝票一覧・請求書一覧など他の検索画面にも展開する
- 検索対象プロパティをUI上でユーザーが選択できるようにする（今回は「対象プロパティは固定で複数列に広げる」までで、選択UIまでは作らない）
- `R-0084` として別途要望台帳に記録し、優先順位が付いたら着手する

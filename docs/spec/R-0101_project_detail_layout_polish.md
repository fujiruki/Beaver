# R-0101: 案件編集画面の入力欄レイアウト改善（工数目安・日付欄）

## 背景
R-0080フィードバック（id=13, 14、2026-08-06）より。

> id=13: 工数目安を入力するところが案件編集画面にありません。追加して。
> id=14: 工数目安入力がありました。もっと入力しやすいUIを用意してほしい。受注日、開始日、納品日、納期など全体的に入力欄の幅を適切な幅に縮めて。スペースが勿体無い。工数目安は、0.5とか20とか100とかなので、5文字も入ればいいと思う。工数目安は「工数目安（h)」として単位も表示して。工数目安の欄は納品日の下にして。

id=13は、その時点では見積伝票が無く手動入力欄自体は存在していたはずだが見つけづらかった/見落とされたと考えられる（id=14で「入力がありました」と本人が続けて報告しているため）。id=14の具体的な改善要望に対応する。

## 対象
`frontend/src/pages/ProjectDetail.tsx`

## 変更内容

1. **工数目安欄の移動**: 現在「備考」欄の後（298〜312行目付近）にある「工数目安」の`Field`を、「納期」欄（273〜275行目）の直後（「施主」欄の前）に移動する
2. **ラベル変更**: 「工数目安」→「工数目安（h）」
3. **入力欄の幅を縮める**: 手動入力時の`<input type="number">`（304〜310行目）に、5〜6文字分程度の狭い幅（例: `w-20`程度、Tailwindで実測して自然な幅に調整）を指定する。見積伝票からの自動計算時の読み取り専用表示も同様に幅を詰める
4. **日付欄（受注日・開始日・納品日・納期）の幅を縮める**: 263〜275行目の4つの日付`<input type="date">`が現在`inputCls`（`w-full`）でグリッドセルいっぱいに広がっている。ブラウザネイティブの日付ピッカーは値の表示に必要な幅が決まっているため、`w-full`をやめて適切な固定幅（例: `w-40`程度）に変更し、余った空間を無駄にしないレイアウトにする（グリッドの列数・配置は既存の2カラムのままでよいが、入力欄自体を必要幅に収める）

## 受け入れ条件
1. 案件編集画面で、工数目安欄が納期の直下に表示される
2. ラベルが「工数目安（h）」になっている
3. 工数目安・受注日・開始日・納品日・納期の入力欄が、内容に対して適切な幅（無駄なスペースが無い）になっている
4. 既存の保存・バリデーション動作は変わらない
5. 既存のvitestテスト（ProjectDetail関連）が壊れないこと。レイアウト変更に伴うテストがあれば更新する

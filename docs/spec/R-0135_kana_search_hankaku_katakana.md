# R-0135: 得意先検索が半角カタカナ表記の読みがなにヒットしない

## 背景

本番フィードバック（/readyoubou、2026-09-01）:

id=41（案件新規作成画面）:
> 「得意先検索でキーワード検索の対象が得意先名だけになってる？住所や読みがなとか備考もキーワード検索対象にしてほしい。」

藤田晴樹さんの追加回答:
> 見てみた。読みがなが「カドタグミ」という表記だった。こういう表記ゆれも対象にして。

id=43（得意先詳細画面 `/customers/50`）:
> 「この得意先が「かどた」という検索でもひっかかるようにしたい。まだひっかからない。」

## 原因（指揮役が本番DBを読み取り専用で確認・特定済み）

本番の得意先id=50（名前「門 田  組」）の`name_kana`は**半角カタカナ「ｶﾄﾞﾀｸﾞﾐ」**で登録されている（Accessからの同期データによるものと推測、他の得意先にも同様のデータがある可能性がある）。

- `api/search_helpers.php`の`buildMultiColumnSearchClause()`は`mb_convert_kana($token, 'c')`/`'C'`で「全角ひらがな⇔全角カタカナ」の変換のみ行っており、半角カタカナへの変換・半角カタカナからの変換を行っていない。検索語「かどた」から生成される`LIKE`パターンは`%かどた%`・`%カドタ%`のみで、半角カタカナの`name_kana`にはヒットしない
- `frontend/src/components/ComboSelect.tsx`の`normalize()`も同様に全角カタカナ（`ァ-ヶ`）のみをひらがな相当へ変換しており、半角カタカナ（`｡-ﾟ`）は正規化対象外。案件新規作成画面の得意先ComboSelect（`ProjectDetail.tsx`）も同じ原因でヒットしない

指揮役が検証済み: `mb_convert_kana($token, 'KVC')`は入力がひらがな・全角カタカナ・半角カタカナのいずれであっても、濁点・半濁点を結合した全角カタカナへ正規化する。この結果を基準に`mb_convert_kana($katakana, 'c')`で全角ひらがな、`mb_convert_kana($katakana, 'k')`で半角カタカナを導出すれば、検索語「かどた」から`["かどた", "カドタ", "ｶﾄﾞﾀ"]`の3バリアントが得られ、ひらがな／全角カタカナ／半角カタカナいずれで格納された`name_kana`にも一致することを実クエリで確認済み。

```php
// 実証済みの検証例（PHP）
function variants(string $token): array {
    $kata = mb_convert_kana($token, 'KVC'); // 任意の表記 → 全角カタカナ（濁点結合込み）に正規化
    $hira = mb_convert_kana($kata, 'c');    // 全角カタカナ → 全角ひらがな
    $hank = mb_convert_kana($kata, 'k');    // 全角カタカナ → 半角カタカナ
    return array_unique([$token, $kata, $hira, $hank]);
}
// variants('かどた') === ['かどた', 'カドタ', 'ｶﾄﾞﾀ']（重複除去後）
// 「かどたぐみ」「カドタグミ」「ｶﾄﾞﾀｸﾞﾐ」いずれの name_kana にもヒットすることを確認済み
```

## 対応方針（藤田晴樹さん承認済み・2026-09-01）

### バックエンド: `api/search_helpers.php`
`buildMultiColumnSearchClause()`内の`$variants`生成を、現行の2バリアント（元のトークン・全角ひらがな・全角カタカナの3種、実質2〜3個）から、半角カタカナ変換を含む形へ拡張する。上記の`KVC`起点の導出方法（`$kata = mb_convert_kana($token, 'KVC')`、そこから`'c'`で全角ひらがな・`'k'`で半角カタカナを導出）を使う。`array_unique([$token, $kata, mb_convert_kana($kata, 'c'), mb_convert_kana($kata, 'k')])`のような形にする。

この関数は得意先検索（`customers.php`）だけでなく、他エンティティの検索（R-0084 Phase2で追加された建具台帳・伝票・請求書一覧の検索）でも共用されているため、修正すればそれらにも自動的に効果が及ぶ。

### フロントエンド: `frontend/src/components/ComboSelect.tsx`
`normalize()`が半角カタカナ（`｡-ﾟ`の範囲）も正規化対象に含めるよう拡張する。半角カタカナをまず全角カタカナへ変換してから、既存の全角カタカナ→ひらがな変換ロジックに通す形にする（JavaScriptには`mb_convert_kana`のような組み込み関数が無いため、半角カタカナ→全角カタカナの変換テーブルまたは正規表現ベースの変換ロジックを自前で実装する。半角カタカナは濁点・半濁点が独立した文字（`ﾞ`＝U+FF9E、`ﾟ`＝U+FF9F）として続くため、結合処理も必要）。

`ComboSelect`はプロジェクト全体で複数箇所（得意先選択・建具台帳選択等）から使われている共通コンポーネントのため、修正すればそれらにも自動的に効果が及ぶ。

### 対象外
DBの`name_kana`データ自体（半角カタカナ登録）は今回変更しない。表記統一（半角→全角への一括変換等）は別要望として扱う。

## TDD必須

`api/tests/test_customers.php`（または新規`api/tests/test_search_helpers.php`）に、`name_kana`が半角カタカナ（例: `ｶﾄﾞﾀｸﾞﾐ`）で登録された得意先が、ひらがな検索語（例: `かどた`）でヒットすることを検証するテストケースを追加する。可能であれば`buildMultiColumnSearchClause()`自体の単体テストも追加する。

先に失敗するテストを書いてから実装すること（Red→Green）。

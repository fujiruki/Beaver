# R-0148: 案件選択時に伝票の得意先をデフォルト設定する

## 背景

藤田晴樹さんより会話内で直接（2026-10-04、`docs/requests.md` §34）:

> 「案件に紐づいて伝票がつくられるときには　その案件の得意先がその伝票の得意先にもデフォルトとして設定されるようにしてね」

## 調査結果

案件詳細画面（`ProjectDetail.tsx`）の「新規見積」「新規売上」ボタン（409・445行目付近）は、既に`customer_id`をURLクエリ（`/vouchers/new?project_id=...&customer_id=...`）で渡しており、この経路では得意先が引き継がれる。

一方、伝票編集画面（`VoucherEdit.tsx`）を直接開いて新規伝票を作る場合、ヘッダーの案件プルダウン（`VoucherHeader.tsx`の`project_id`の`<select>`、52行目付近）で案件を選択しても、得意先（`customer_id`）は自動設定されない。既存の`projects`一覧（`useProjects()`で取得済み）には各案件の`customer_id`が含まれている。

## 対応方針

`VoucherEdit.tsx`に、新規伝票作成時（`isNew === true`）限定で以下の副作用を追加する。

- `project_id`フィールドの変更を監視する（`watch('project_id')`）
- 値が変化し、かつ現在の`customer_id`が未設定（空文字列 `''` または `'0'`）の場合のみ、選択された案件（`projects`から`id`で検索）の`customer_id`を`setValue('customer_id', ...)`で反映する
- 既に得意先が設定されている場合（手動選択済み、またはURLクエリの`customer_id`で初期値が入っている場合）は上書きしない
- 既存伝票の編集（`isNew === false`）では一切発動しない（案件を後から変更しても得意先は自動では変わらない。意図しない書き換え防止）
- 案件に`customer_id`が無い（null）場合は何もしない

## TDD

`VoucherEdit`のテスト（`frontend/src/pages/__tests__/`）に追加:
1. 新規伝票作成中、得意先未選択の状態で案件プルダウンから案件を選ぶと、得意先セレクトがその案件の得意先に自動設定される
2. 得意先を先に手動選択してから案件を選んでも、得意先は上書きされない（手動選択を尊重）
3. 既存伝票の編集画面で案件を変更しても、得意先は自動変更されない
4. 選択した案件に得意先が設定されていない場合、得意先セレクトは変化しない

## 受け入れ条件

1. 案件詳細画面からの新規伝票作成（既存動作）は変化なし
2. 伝票編集画面を直接開いて新規作成する際、案件を選ぶと得意先が未設定なら自動的に案件の得意先が設定される
3. 得意先を手動選択済みの場合は案件選択で上書きされない
4. 既存伝票の編集では発動しない
5. 既存テスト・回帰スイートが通る

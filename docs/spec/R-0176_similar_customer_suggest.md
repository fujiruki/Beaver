# R-0176: 得意先の新規登録で似た得意先を候補に出す（二重登録の防止）

- 受付: 2026-10-15 dodai-back（AccessTategu側）から依頼、藤田晴樹さん了承済み
- 状態: 仕様確定

## 背景

AccessとBeaverの両方で同じ得意先を作ってしまう二重登録（同期パターン表K7）を、入力の時点で防ぐ。晴樹さんは得意先・案件の新規登録をBeaverで行う運用なので、Beaverの新規登録画面がいちばん手前の防ぎ所になる。Access側でも、Beaverで作られた得意先が承認待ちに入るときに同じ照合をする（Access側で別途実装）。

## API: `GET /customers/similar`

クエリ: `name`、`name_kana`、`tel`（どれも省略可。全部空なら空配列）

照合の対象はBeaverの全得意先。Accessから同期された分も、`is_active = 0`も含める。

一致の規則（どれか1つでも当たれば候補にする）:

1. 名前: 両方を正規化し、片方がもう片方を含めば一致。正規化後の入力が2文字未満なら名前では照合しない
2. カナ: `name_kana`同士を同じ正規化で比べる。規則は名前と同じ
3. 電話: 入力を数字だけにして`tel`・`mobile`・`fax`それぞれ（同じく数字だけにしたもの）と完全一致。数字が6桁未満なら照合しない（AccessのDodaikun_CustomerMatchのTelSetMatchesと同じ考え方）

正規化の手順:
- NFKCで半角・全角をそろえる
- 空白（半角・全角）、中黒「・」、記号（`()（）.,、。-ー`は除く）を取り除く
- 法人格の表記を取り除く: 株式会社・有限会社・合同会社・合資会社・合名会社・(株)・(有)・(合)・㈱・㈲、カナの「カブシキガイシャ」「カブシキカイシャ」「ユウゲンガイシャ」「ユウゲンカイシャ」「ゴウドウガイシャ」
- カタカナをひらがなにそろえる（既存の検索のR-0090・R-0135の正規化を再利用できれば再利用する）
- 2026-10-15追記（dodai-backとAccess側`Dodaikun_CustomerMatch.bas`の照合をそろえる）:
  - 法人格に追加: 一般社団法人・医療法人・社会福祉法人・学校法人・宗教法人、全角括弧の（株）（有）（合）
  - カナの法人格の略記を取り除く: カ）（カ ユ）（ユ（半角・全角括弧どちらも。ひらがなにそろえた後なら か）（か ゆ）（ゆ）。記号を取り除く前に処理する
  - 末尾の敬称を取り除く: 御中・様・殿・邸・宅（末尾にあれば、無くなるまで繰り返し除く）。名前とカナの両方に適用し、照合する両側（入力と既存）に同じ処理をかける
  - 電話: 数字だけにしたあと、先頭が81なら0に置き換える（+81表記への対策）
  - Access側との違いで今のままにするもの: 電話の下限（Accessは9桁、Beaverは6桁）、名前の下限（Accessは3文字、Beaverは2文字）。候補は広めに出してよいため

応答（最大10件。電話一致→名前一致→カナ一致の順、同じ順位の中ではcode順）:

```json
[{"id":1,"code":"...","name":"...","name_kana":"...","tel":"...","mobile":"...","address1":"...","is_active":1,"access_customer_no":"...","matched":["tel","name"]}]
```

## 画面

対象は2か所: 得意先の新規登録（`CustomerDetail.tsx`の新規モード）と、案件画面から開く新規得意先モーダル（`NewCustomerModal.tsx`）。既存得意先の編集画面には出さない。

1. 名前・カナ・電話・携帯の入力が変わったら、0.3秒ほど待ってから`/customers/similar`を呼ぶ（電話は`tel`と`mobile`のうち入力のある方を順に照合する。1回の呼び出しで足りなければ2回呼んで結果をまとめてよい）
2. 候補があれば、入力欄の近くに「似た得意先があります。同じ得意先ならそちらを使ってください」と一覧を出す。各行に、コード・名前・カナ・電話・住所1・一致した項目（電話／名前／カナ）を表示する。`is_active = 0`の行には「無効」と表示する
3. 候補を選んだときの動き:
   - 得意先の新規登録画面: その得意先の詳細（`/customers/{id}`）へ移る（新規登録をやめる）。入力途中の内容は捨ててよい
   - 案件画面のモーダル: その得意先を選んだものとして扱い（新しく作ったときと同じく`onCreated`に既存の得意先を渡す）、モーダルを閉じる
4. 候補は無視してそのまま登録できる。登録をブロックしない。確認ダイアログも出さない
5. 候補の取得に失敗しても入力・登録は妨げない（何も出さない）

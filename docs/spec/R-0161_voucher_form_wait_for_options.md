# R-0161: 伝票画面は選択肢の読み込みが終わってからフォームに値を入れ、それまで自動保存しない

- 状態: 確定（2026-10-10）
- 起点: dodai-backより（2026-10-10朝に5810で発見、同日夜にR-0168デプロイ後の5809で再発。藤田晴樹さんのスクリーンショット）
- 優先度: 高（本番切替A-X-02の前に必須。dodai-backの依頼）
- 関連: R-0164（ヘッダー自動保存）、R-0168（開くたびに取り直す）

## 要望の原文（dodai-backより）

> Beaver_beta /vouchers/5809、R-0168 デプロイ後、Ctrl+F5 で再読み込みしたあとで、得意先が「-- 選択してください --」、案件が「-- 案件なし --」、売上種別が「-- 種別なし --」と、選択肢がすべて空で表示されていました。実データは正しく入っています（customer_id=809、project_id=48、sales_category_id=1）。
> 心配な点: R-0164 の自動保存はヘッダーの全項目を送ります。選択肢が空のまま表示された状態で、晴樹さんが摘要などほかの項目を直すと、customer_id・project_id・sales_category_id が空（null）で保存され、Access にも伝わって得意先が消えるおそれがあります。
> 1. 選択肢（得意先・案件・売上種別など）の読み込みが終わるまでは、フォームに値を入れない／自動保存しない。表示が空のときの値を保存しない、という形にしてください。
> 3. 本番に入れる前に必ず直してください（R-0161 の優先度を上げる）。

## 原因（指揮役の確認）

`VoucherEdit.tsx` は伝票の取り直しが終わると `reset(toFormValues(voucher))` でフォームに値を入れる。得意先・案件（`useCustomers`・`useProjects`）と売上種別（`VoucherHeader` 内の `useSalesCategories`）の選択肢は別のクエリで、伝票より後に届くことがある。選択肢の無い `<select>` に値を入れるとブラウザは先頭の選択肢を表示し、後から選択肢が届いても戻らない。R-0168で開くたびに伝票を取り直すようにしたため起きやすくなった。

2026-10-10 時点の Beaver_beta では、空で上書きされた伝票は無い（今日更新された5809・5810とも得意先・案件・売上種別あり、customer_id が NULL の伝票は0件）。

## 仕様

1. 伝票編集画面は、伝票の取り直しに加えて、得意先・案件・売上種別の選択肢の読み込みがすべて終わってから、フォームに値を入れる（`reset`）。それまではヘッダーの入力欄を読み込み中として扱い、操作させない
2. フォームに値を入れる前は、ヘッダーの自動保存も明細の保存も送らない
3. 選択肢の読み込みに失敗したときは、フォームに値を入れず、「選択肢を読み込めませんでした。再読み込みしてください」を表示する。自動保存はしない
4. 新規作成画面も、選択肢がそろうまで「保存」（作成）を押せない
5. 伝票に入っている得意先・案件・売上種別が選択肢の中に無い場合（無効化された得意先など）でも、その値を空に変えて保存しない。選択欄にはその値を「（一覧にない得意先 id=…）」のような選択肢として出す

## 受け入れ条件（vitest）

1. 伝票の取得は即座に、得意先・案件・売上種別の取得は遅れて返る状態で画面を開く → 選択肢が届いたあと、得意先・案件・売上種別の選択欄に伝票の値（例: 809・48・1）が選ばれて表示される
2. 1の状態で、選択肢が届く前にPUTが一度も送られない。届いたあとに摘要を変えると、PUTの本文の customer_id・project_id・sales_category_id は伝票の値のまま
3. 得意先の取得が500 → フォームに値を入れず、読み込み失敗の案内が出て、摘要を変えてもPUTが送られない
4. 伝票の customer_id が得意先一覧に無い → 選択欄にその値が選ばれた状態で表示され、摘要を変えたときのPUTの customer_id はその値のまま
5. 既存テスト（R-0164・R-0166・R-0168ほか）は期待値を変えずに通る

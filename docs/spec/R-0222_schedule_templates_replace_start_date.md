# R-0222: 製作も予定の1行にして開始日の欄をなくす・決まった種類の行・見込み時間・全体の薄い枠

- 状態: 仕様化済み（2026-10-30）
- 要望の原文: `docs/requests_log.md` の R-0222
- 関係する仕様: R-0220（案件の予定）、R-0111（段取りの製作のバー）、R-0223（際限ないスクロール）

## 晴樹さんの決定（2026-10-29〜30）

1. 製作も予定の1行にする。案件の「開始日」の欄はなくし、製作の予定がそのかわりになる（「今やる理由が弱い」は誤り。書きにくいままだと整理されない）
2. 案件を作ったら、決まった種類の行が日付・時間の空の状態で出ていて、記入した行だけが本物の予定になる。決まった種類は **現調・見積・製作・取付** の4つ
3. 予定ごとに見込み時間を書く
4. 段取りの行に、予定の最初から最後までを薄い枠で出す（製作のバーと予定の全部、済も含む）
5. Youkan とは今回はデータの形を合わせるだけ。連携は別の要望

## データ

### `project_schedules` の変更（migration 041）

- `end_date` を NULL 可にする（SQLite のため表を作り直す。既存の行・id はそのまま移す）
- `hours REAL`（NULL 可）を足す。見込み時間（時間）
- 種類に「製作」を足す。種類の一覧: 現調／見積／見積依頼／打合せ／材料発注／外注依頼／製作／取付／その他
- 検査: `start_date` と `end_date` が両方あるときは `start_date <= end_date`。`hours` は0以上。日付も時間も無い行は作らない（422）

### 開始日を製作の予定へ移す（migration 041 の中）

- `projects.start_date` が入っていて、製作の予定がまだ無い案件ごとに、製作の予定を1行作る（`start_date` = 案件の開始日、`end_date`・`hours` は空）
- 何度流しても二重にならない形（製作の予定が無い案件だけ）にする

### `projects.start_date` は写しとして残す

- 案件の画面から開始日の欄はなくすが、列は残す。中身は「その案件の製作の予定の開始日のうち一番早いもの（無ければ NULL）」の写しとし、予定を足す・直す・消すたびにサーバーが入れ直す
- 写しを入れ直しても `projects.updated_at` は進めない（Access の同期に影響させない。Access と Youkan は開始日を使っていない）
- 案件の作成・更新（`POST/PUT /projects`）で送られてきた `start_date` は書かない（無視する）
- 案件の一覧の「開始日」の列は「製作開始」に名前を変え、写しを出す（並べ替えもそのまま）

## 画面

### 案件の画面の「予定」の表

- 開始日の欄をなくす
- 表の列: 種類・開始・終了/期限・時間・メモ・済・削除
- 決まった種類（現調・見積・製作・取付）のうち、まだ予定が無い種類は、薄い字の行として表の上に出す（保存されていない行）。開始・終了/期限・時間のどれかを入れたら、その行を予定として作る。入れていない行は「まだ考えていない」として表示だけ
- 決まった種類の行は、その種類の予定が1行でもできたら薄い字の行を出さない（2本目は末尾の空の行から足す）
- 決まった種類以外は、今までどおり末尾の空の行から足す
- 製作の行で終了を空にしたら、「（時間から）」と薄く出す（下の自動の長さ）
- 時間は右寄せ、小数1桁まで（例 2、1.5）

### 段取りの画面

- 製作のバーは製作の予定から描く。1つの案件に製作が2行あれば2本描く
  - 開始は予定の `start_date`。終了は `end_date` があればそれ、無ければ今と同じく工数から出す（予定の `hours` があればそれ、無ければ案件の工数 `effective_estimated_hours`。土日を数えない今の `barEndDate`）
  - 開始日の無い製作の予定（時間だけ）はバーを描かない
- 製作のバーのドラッグは、その製作の予定の `start_date`（`end_date` があれば同じ日数だけ）を動かす
- 未着手の一覧の「今日に置く」「次の空きに置く」は、製作の予定を作る（その案件に開始日の無い製作の予定があればそれに開始日を入れる）
- ラベル: 予定は「見積 2h」のように種類名の横に時間を出す。製作のバーは「案件名（時間h）」のまま（時間は予定の `hours`、無ければ工数）
- **全体の薄い枠**: 行ごとに、その案件の予定（済も含む、製作のバーの自動の終わりも含む）の一番早い日から一番遅い日までを、薄い琥珀色の点線の枠（`#b07a2e` を薄くしたもの）で、行の高さいっぱいに囲む。バーより下に描き、ドラッグの邪魔をしない。日付のある予定が1つだけなら、その予定の範囲
- 行に出す案件: 日付のある予定（製作を含む）が1つ以上ある案件。ヘッダーの「開始日未設定 n件」は「予定なし n件」にし、日付のある予定が無い案件を数える
- 稼働数: 製作のバーと取付（どちらも済でないもの）を数える。見積などは数えない（R-0220 と同じ）
- 簡単編集（`ProjectQuickEditModal`）の開始日の欄はなくす
- 「やること」の一覧: 日付の無い予定は一番下に「日付未定」としてまとめる

### 対象外

- Youkan への連携（別の要望）
- 折り返しモードへの予定の表示（R-0220 と同じく出さない）

## 受け入れ条件

1. migration 041 で、開始日が入っている案件それぞれに製作の予定が1行でき、もう一度流しても増えない。既存の予定はそのまま残る
2. 案件の画面に開始日の欄が無く、予定の表に現調・見積・製作・取付の薄い字の行が出る。時間だけ入れても予定になる
3. 製作の予定の開始を変えると、段取りのバーが動き、`projects.start_date` の写しが変わり、`projects.updated_at` は変わらない
4. 製作の終了が空なら、バーの長さは時間（無ければ工数）から出る
5. 段取りの行に、予定全体の薄い枠が出る
6. `POST/PUT /projects` の `start_date` は無視される
7. 回帰スイート（vitest＋PHPテスト）が全部通る

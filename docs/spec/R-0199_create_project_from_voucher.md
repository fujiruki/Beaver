# R-0199: 割り当てモードで伝票から案件を作って入れる（得意先＋摘要で案件を作成）

- 依頼: 2026-10-25 藤田晴樹さん（このセッションで直接）
  - 「割り当てを決めないことにした伝票があるんだ、伝票を作ったけど、案件を発行して管理するまでもない小さい仕事の伝票とか、でもそれが右側伝票リストの上位に残り続けると邪魔だ・・・どうしたらいいんだろう」
  - 3案（「案件にしない」印／小口案件にまとめる／古い伝票を隠す）を示し、いったん「案件にしない」印を選んだあと、「小口案件のほうがいい！」「小口案件でまとめる方がプロパディを増やさなくて済むしスマートだよね！」「あ、じゃなくて、」「その得意先名とその適用名で案件を作成して突っ込んで欲しい」
  - 作った案件の状態: 「売上は完了、見積は見積済」（質問で選択）
- 状態: 仕様確定
- 解釈: 「適用名」は「摘要」。列を増やさず、伝票ごとに、その得意先とその摘要で案件を1件作り、その伝票を入れる。「案件にしない」印（列の追加）は作らない

## 動き

- 割り当てモードで、伝票から「この伝票で案件を作る」を選ぶと、次の案件を作り、その伝票を入れる
  - 得意先: 伝票の得意先
  - 案件名: 伝票の摘要。摘要が空なら「伝票番号の案件」（例: 「S08468の案件」）
  - 状態: 売上伝票から作ったら「完了」、見積伝票から作ったら「見積済」
  - ほかの項目（日付・住所など）は空
- 作ったら、その伝票は右の一覧から消え、「元に戻す」付きのお知らせを出す。「元に戻す」で伝票の案件を外し、作った案件を消す（案件の削除は既存の仕組みに従う）
- 左の案件一覧に、作った案件が出る（R-0198の絞り込み中なら、その得意先の案件として出る）
- 得意先が未設定の伝票では作れない（ボタンを押せない）

## 選び方

- 右の引き出し（R-0197）に「この伝票で案件を作る」ボタン
- 左の案件一覧の上に「新しい案件にする（ここへ落とす）」の置き場。伝票をここへドラッグしても同じ動き
- R-0195（ドラッグで既存の案件へ）・R-0197（ダブルクリックで詳細）・R-0198（クリックで得意先に絞り込む）はそのまま

## API

- 新しいAPIは作らない。既存の案件作成（`POST /projects`）と伝票の案件の変更（`PUT /vouchers/{id}`の`project_id`だけ、R-0196）を順に呼ぶ。案件の作成に失敗したら伝票は変えない。伝票の変更に失敗したら作った案件を消してエラーを出す
- 請求済みの売上でも作れる（R-0196で`project_id`だけの変更は通る）

## 受け入れ条件（テスト）

1. 引き出しの「この伝票で案件を作る」で、得意先＝伝票の得意先、案件名＝摘要、状態＝売上なら「完了」・見積なら「見積済」の`POST /projects`が出て、続けてその案件の`project_id`だけの`PUT /vouchers/{id}`が出る
2. 摘要が空なら案件名は「伝票番号の案件」
3. 置き場へドラッグしても1と同じ
4. 作ったあと伝票が右の一覧から消え、「元に戻す」で伝票の案件を外すPUTと案件の削除が出る
5. 得意先が未設定ならボタンを押せず、置き場に落としても何もしない
6. 案件の作成に失敗したら伝票のPUTは出ない。伝票のPUTに失敗したら作った案件の削除が出る
7. R-0195〜R-0198のテストが通る

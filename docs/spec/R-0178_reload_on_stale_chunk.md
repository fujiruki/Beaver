# R-0178: デプロイ後に古いタブで画面の読み込みエラーが出たら自動で1回だけ再読み込みする

- 受付: 2026-10-15 藤田晴樹さん。Beaver_betaの案件画面で「Unexpected Application Error! Failed to fetch dynamically imported module: …/assets/ProjectDetail-CXlUzxE0.js」が出た件で、指揮役の提案に「仕組みを入れる」
- 状態: 仕様確定（本番切替（A-X-02）の前に入れる）

## 背景

画面はページごとにJSファイルを分け、開くときに読み込む（`App.tsx`の`lazy(() => import(...))`）。ファイル名にはビルドごとに変わる文字列が付き、デプロイで古いファイルはサーバーから消える。デプロイ前から開いていたタブで別の画面へ移ると、古いファイル名を読みに行き、サーバーはHTMLを返すため、React Routerのエラー画面になる。本番に切り替えた後は、デプロイのたびに開きっぱなしの人に起きる。

## 動き

1. 画面のJSファイルの読み込みに失敗したら（Viteの`vite:preloadError`イベント、または`lazy`の`import()`が「Failed to fetch dynamically imported module」等で失敗したとき）、ページを1回だけ自動で再読み込みする。再読み込み後は移ろうとしていた画面（今のURL）が開く
2. 無限に再読み込みしないよう、直前の自動再読み込みから10秒以内にもう一度失敗したら再読み込みせず、エラーを表示する。記録は`sessionStorage`に`{AppID}_chunk_reload_at`（AppIDは`lib/appId`の値）で持つ
3. 2のときと、ほかのエラーのときに出す画面は、React Routerの開発者向けの既定画面ではなく、「画面を読み込めませんでした。ページを再読み込みしてください。」と「再読み込み」ボタンを出す（ルートの`errorElement`）
3b. 2026-10-15追記（藤田晴樹さん「ああいうときに日本語でもメッセージ出す」）: 英語の開発者向け画面は出さず、すべて日本語で伝える
   - 自動で再読み込みする直前に、画面の中央に「Beaverが新しくなりました。画面を読み込み直しています…」を表示してから再読み込みする
   - 読み込みエラーで再読み込みしなかったとき（2のとき）のエラー画面は「Beaverが新しくなったため、画面を読み込めませんでした。」「再読み込み」ボタンにする。読み込みエラー以外のエラーは3の文言のまま。どちらも英語の技術的なメッセージは出さない（開発環境でだけ、下に小さく出すのはよい）
4. 伝票画面などに保存していない入力がある場合も再読み込みしてよい（読み込みエラーは別の画面へ移るときに起きるもので、R-0168の離脱ガードを通った後のため）

## 受け入れ条件（テスト）

vitest:

1. `vite:preloadError`が起きると`location.reload`が1回呼ばれ、`sessionStorage`に時刻が記録される
2. 記録から10秒以内にもう一度起きると`reload`は呼ばれない
3. 10秒より後なら再び`reload`が呼ばれる
4. ルートのエラー画面に「画面を読み込めませんでした」と「再読み込み」ボタンが出る。読み込みエラーで再読み込みしなかったときは「Beaverが新しくなったため、画面を読み込めませんでした。」が出る。英語の「Unexpected Application Error」は出ない
4b. 自動再読み込みの直前に「Beaverが新しくなりました。画面を読み込み直しています…」が表示される
5. 既存のテストと回帰スイートが通る

手動（beta）:

6. 案件画面を開いたままデプロイし、そのタブで別の画面へ移ると、エラー画面を出さずに目的の画面が開く

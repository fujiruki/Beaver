# R-0241 伝票に「非表示記録」を足し、Access と両方向で同期する

出どころ: 晴樹さんの答え（dodai-back 経由、2026-11-03）。Access 側は F-25（R-0216）。

## 決まり
1. **列**：`vouchers.hidden_note TEXT`（NULL 可）を migration 043 で足す。名前は Access の列と同じにする。void（取消）とは別のもの。
2. **画面**：伝票のヘッダーの「説明」（R-0236、`memo`）の下に「非表示記録」の欄を出す。複数行、説明と同じ作り。見出しの横に小さく「帳票に出ない」と添える。保存は今のヘッダーと同じ（編集は欄から出たときに自動保存、新規は保存ボタン）。読み取り専用の伝票では表示だけ。
3. **帳票**：見積書・印刷（プレビュー）には出さない。「AI宛にコピー」（R-0233）には出す（値付けの相談に使うため。見出しは「非表示記録（社内メモ）」）。
4. **API**：`POST /vouchers`・`PUT /vouchers/{id}` で受ける。文字数の上限は説明と同じ扱い（R-0190 の決まりに合わせる）。
5. **同期**：`/vouchers/sync` の受け口は、キーがあれば更新（null なら空）、無ければ今の値を残す（R-0236 の memo と同じ書き方）。返り値（`VOUCHER_SYNC_SELECT_COLUMNS`）に入れる。
6. 取付場所№は同期しない（今のまま名前だけ）。得意先の取引区分・消費税区分は、dodai-back の調べ（R-0217）が終わるまで変えない。

## 受け入れ条件
- migration 043 を当てると列ができ、2回当てても壊れない（他の migration の書き方に合わせる）。
- 画面で書いて欄から出ると `PUT` に `hidden_note` が入る。印刷に出ない。AI宛にコピーには出る。
- 同期: キーありで更新、null で空、キーなしは前の値のまま。返り値にある（PHP テスト、本物の SQLite）。

## 本番
migration を含むので、本番の DB に当てる前に晴樹さんに確かめる。同期の窓口に関わるので、R-0236・R-0238・R-0239 と同じ日に、dodai-back と合わせて Beaver が先に入れる。

# R-0258・R-0259・R-0260 伝票の編集画面: 明細の原価を1個あたりで出す／利益率のボタンをサマリーへ／明細の見出しをついてこさせる

原文は requests_log の各要望。見た目の作りは今の伝票の画面（R-0230）のまま。新しい色・大きさを作らない。

## R-0258 明細の原価を1個あたりで出す（`components/voucher/LineItemRow.tsx`）
- 各行の「材料原価 ¥…」「労務費 ¥…」「製造原価 ¥…」を1個あたり（数量を掛けない）にする。例: 本体1,160・工場0.6h・現場0.9h・労務単価4,000・数量20 → 材料原価 ¥1,160、労務費 ¥6,000、製造原価 ¥7,160（今は ¥23,200／¥120,000／¥143,200）。
- 「単価」（1個あたり）と「金額」（単価×数量）は今のまま。
- 右端の「利益・利益率・粗利率・日割粗利」は今のまま行全体（数量を掛けた値）。※晴樹さんに確認中。違えば直す。
- 伝票全体の合計・サマリーの数字は変えない（計算は今のまま。表示だけ）。

## R-0259 利益率のボタンと「原価から売値を設定」を右のサマリーへ（`pages/VoucherEdit.tsx`、`ProfitRateBar`、`TotalSummary.tsx` の TopSummary）
- 今の利益率のバー（10%〜40% と「原価から売値を設定」）を、右のサマリー（スクロールしてもついてくる欄）の中、数字の下に移す。動き（選んでいる行が対象、行を選んでいなければ全行）は変えない。対象がわかる表示があれば一緒に移す。
- 画面が狭くてサマリーが明細の上に出るときは、利益率のバーを明細の見出し（R-0260）と一緒に画面の上にくっついてくる帯に入れる。
- 明細の上の元の場所からは消す（2か所に出さない）。

## R-0260 明細の見出しをついてこさせる
- 「No／取付場所・品名／数量・備考／本体／金物／ガラス／工場h／現場h／労務単価…」の見出しを、縦にスクロールしても画面の上にくっついてくるようにする（position: sticky）。上に固定の帯（アプリのナビなど）があればその下にくっつく。
- 明細は横スクロールする箱の中にある。sticky は overflow の箱の中では効かないことがあるので、縦はページのスクロールでくっつき、横は明細と同じだけ一緒に動くようにする（必要なら見出しを箱の外に出し、横位置を明細のスクロールに合わせて動かす）。どう作ったかを報告する。

## 受け入れ条件
- vitest: 数量20の行で材料原価・労務費・製造原価が1個あたりの値。単価・金額・利益は今の値のまま。
- vitest: 利益率のバーがサマリーの中にあり、明細の上には無い。押したときの動き（選んでいる行／全行）は既存のテストのまま通る。
- ブラウザ（beta で指揮役が確かめる）: 明細が多い伝票で下までスクロールしても、見出しと利益率のボタンが見える。横スクロールしても見出しと列がずれない。1440px と 1920px で。

## R-0259 追加（2026-11-10、晴樹さん）
- 行の操作のボタン（製品複製・行を挿入・行を削除・▲・▼）も、利益率のボタンと一緒に右のサマリーの中へ移す。動き（選んでいる行が対象）は変えない。明細の上の元の場所からは消す。
- 画面が狭くてサマリーが明細の上に出るときは、利益率のボタンと同じく、明細の見出しと一緒に上にくっつく帯に入れる。
- 受け入れ条件: 行の操作のボタンがサマリーの中にあり、明細の上には無い。押したときの動きの既存のテスト（行を挿入・▲▼・削除・製品複製）がそのまま通る。

# R-0086 / R-0087 / R-0088: 案件一覧・案件編集画面の改善

## 背景

R-0080フィードバック（id=5, 6, 7、2026-08-05 03:10〜03:13）より。

## R-0086: 案件一覧に「納期」列を追加

> 案件一覧において、納期や取り掛かり日のプロパティも表示して。

`frontend/src/pages/ProjectList.tsx` の`columns`配列（81-119行目）には既に`start_date`（開始日、101行目）列があるが、`delivery_date`（納期）列が無い。`start_date`列の直後に`delivery_date`列（ラベル「納期」、`p.delivery_date ?? '—'`、`sortable: true`）を追加する。バックエンドのGET一覧は既に`p.*`を返しており`delivery_date`はレスポンスに含まれるため、バックエンド変更は不要。

## R-0087: 案件編集画面に得意先のプレビュー表示・編集ボタン・タイトル横の保存ボタン

> 案件編集画面で、得意先の名前の下に、その得意先の住所、電話番号、メールアドレス、備考も小さめの文字で編集不可で表示して。電話番号はタップで電話をかけれるリンクの状態で。メールアドレスもリンクの状態で。また、小さく「得意先を編集」ボタンもつけて。あと、保存ボタンを案件編集というタイトルの右にもつけて。

対象: `frontend/src/pages/ProjectDetail.tsx`

- 得意先の`ComboSelect`（144-163行目）の直下に、選択中の得意先（`customers`から`customerId`で検索）の以下の情報を、小さめの文字（`text-xs text-slate-500`程度）・編集不可のプレビューとして表示する:
  - 住所（`address1`+`address2`）
  - 電話番号（`tel`。`<a href="tel:...">`でタップ発信できるリンクにする。無ければ`mobile`でも可）
  - メールアドレス（`email`。`<a href="mailto:...">`リンクにする）
  - 備考（`memo`）
  - 各項目は値が無ければ表示しない（空欄行を作らない）
- プレビューの近くに小さな「得意先を編集」ボタンを設置する。クリックで得意先詳細（`/customers/{customerId}`）を**新しいタブ**で開く（`window.open`、`target="_blank"`）。案件編集中の未保存内容を失わないため、画面遷移ではなく新規タブにすること
- 得意先が未選択の場合はプレビュー・編集ボタンとも表示しない
- タイトル「案件 編集」（113-118行目）の右側に保存ボタンを追加する。フォーム本体は下部にあるため、`handleSubmit(onSubmit)`を直接呼び出すボタンにする（`<form>`要素の外なので`type="submit"`では効かない点に注意）。既存の下部の保存ボタンはそのまま残す（両方から保存できる状態にする）

## R-0088: 案件コード欄を狭く、案件名欄を広く

> 案件編集画面において、案件コードは10文字入る幅のテキストボックスにして、その右にある案件名のテキストボックスが幅広くできるよね。

対象: `frontend/src/pages/ProjectDetail.tsx` の131-142行目、`<div className="grid grid-cols-2 gap-4">`で案件コード（読み取り専用表示）と案件名を等幅2カラムにしている箇所。案件コードは半角10文字程度が収まる固定幅（例: `grid-template-columns: 140px 1fr` 相当、Tailwindなら`grid-cols-[140px_1fr]`）にし、案件名側を残り幅いっぱいに広げる。新規登録時（`isNew`、案件コード欄が無い）は現状どおり案件名のみ全幅で維持する。

## 受け入れ条件（共通）

1. 案件一覧に「納期」列が表示され、ソート可能なこと
2. 案件編集画面で得意先選択時、住所・電話・メール・備考の非編集プレビューが表示され、電話はtel:リンク、メールはmailto:リンクになっていること
3. 「得意先を編集」ボタンで新しいタブが開き、案件編集画面の入力内容が失われないこと
4. タイトル横の保存ボタンで、下部の保存ボタンと同じ保存処理が実行されること
5. 案件コード欄が狭く、案件名欄が広くレイアウトされること（新規登録画面は現状維持）
6. 既存のvitestテスト（ProjectDetail・ProjectList関連）が壊れないこと。新規・変更箇所にテストを追加すること
7. `npm run build`が通ること

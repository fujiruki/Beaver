# R-0196: 請求済みの売上伝票でも案件だけは変えられるようにする

- 依頼: 2026-10-24 藤田晴樹さん（このセッションで直接）「案件の移動は法律には影響がないから、大丈夫。　請求済みの売上伝票でも案件は編集できるようにしたほうがいいとおもっている　どうかな」
- 状態: 仕様確定
- きっかけ: R-0195（案件一覧の伝票の割り当て）で、請求済みの売上を案件に落とすと`PUT /vouchers/{id}`が`assertVoucherEditable`で409になり、割り当てられないと分かった

## 変更

- `PUT /vouchers/{id}`で、送られた項目が`project_id`だけ（と楽観ロック用の`expected_updated_at`）のときは、請求済み（`status=billed`）・Accessで請求済み（`access_billed_flag=1`）・売上に引用済みの見積でも、`project_id`だけを書き換えて200を返す
- `project_id`以外の項目が1つでも含まれていれば、今までどおり409（請求済みのロックは変えない）
- void済みの伝票は今までどおり変えられない（409）
- 伝票画面: 請求済みの伝票でも「案件」の選択欄だけは変えられるようにし、変えたらその項目だけを保存する。ほかの欄は今までどおり読み取りのみ
- `project_id`を変えると`updated_at`が進む（Accessは次のプルで受け取る。Access側は案件だけの違いを自動で取り込む AccessTategu R-0208 を作成中）

## 受け入れ条件（テスト）

1. `status=billed`の売上に`project_id`だけのPUT → 200、`project_id`が変わる、ほかの列は変わらない
2. `access_billed_flag=1`の売上でも1と同じ
3. 売上に引用済みの見積でも1と同じ
4. 請求済みの売上に`project_id`と別の項目（例: `memo`）を一緒に送る → 409、何も変わらない
5. void済みの伝票に`project_id`だけ → 409
6. 請求済みの伝票の画面で、案件の選択欄は操作でき、ほかの欄は読み取りのみ。案件を変えると`project_id`だけのPUTが出る
7. 案件一覧の割り当てモードで、請求済みの売上を案件に落とすと割り当てられる

# R-0129: ダッシュボード・案件一覧・得意先一覧のスマホ最適化（レスポンシブ対応）

## 背景

藤田晴樹さんより会話内で直接（2026-08-31）:

> ダッシュボード、案件一覧、得意先一覧の画面のスマホ専用デザインを考えてほしい。レスポンシブ対応で行った方がいい？どのように実装したらいいか。スマホで便利に使いたい。しかしまったく違う画面を作ると実装・リニューアル時のコストが上がってしまう。でもスマホで使いやすくしたいというのが大きい。
>
> （中略、レスポンシブ方針への同意を受けて）分かった、レスポンシブでお願いします。設計・実装・デプロイまでして。より使いやすいUIデザイン・余白の調整のためにkaigiしてもいいよ。あくまでビジネスアプリなので、情報を詰めることができるのがいい。

UI設計の詳細は複数視点での検討が必要と判断し、AI専門家会議（kaigi）を実施。議事録: `docs/kaigi/2026-08-31-スマホ最適化UI設計.md`。

会議の結論として「案件一覧・得意先一覧をスマホでどう見せるか」で、全項目を残すカード化案と、主要項目のみに絞る簡素リスト案の2案が拮抗したため、この一点のみ藤田晴樹さんへ確認: **「簡素リスト＋詳細遷移」を選択**（2026-08-31）。

## 対象外（今回は対象としない）

- 別画面・別アプリとしてのスマホ専用UI（レスポンシブで対応するため不要）
- ダッシュボード・案件一覧・得意先一覧以外の画面（伝票一覧・請求一覧・段取りボード等は対象外。将来横展開する場合は別途R-IDを起票する）

## 決定した設計方針（kaigi結論）

- ブレークポイントは Tailwind CSS v4 の既定値 `md`（768px）のみを使用する。独自のブレークポイント定義・カスタム値は追加しない
- 分岐方式はCSSベース（`md:`修飾子によるJSXの出し分け）を基本とする。モバイル用DOMとPC用DOMを両方レンダリングし、`hidden md:block` / `md:hidden` 等のクラスで表示・非表示を切り替える（ウィンドウリサイズ・画面回転への追従をJSリスナーなしで実現するため）
- **新規の共通フック・共通コンポーネントファイルは追加しない**（対象3画面のみのため時期尚早。伝票一覧等に横展開する段階で共通化を再検討する）
- `DataTable.tsx` 本体は無改修。PC表示（`md`以上）は現状のDataTableをそのまま使う
- サイドバー開閉のような「JS状態が必須な箇所」に限り `useState` を使う。それ以外は素朴なCSS分岐で済ませる

## 画面ごとの仕様

### 1. サイドバーナビ（`AppLayout.tsx`）

- **`md`以上（現状維持）**: 常時表示の固定180pxサイドバー。見た目・動作を一切変更しない
- **`md`未満**:
  - サイドバー本体は初期状態で非表示（画面外へオフキャンバス、`translate-x-full`等）
  - 画面上部に「☰」ハンバーガーボタン＋「Beaver」タイトルを表示する軽量ヘッダーバーを追加（新規、`md:hidden`）
  - ハンバーガーボタンタップでサイドバーがオーバーレイ表示される（`open`状態を`useState`で管理）。半透明の背景オーバーレイも表示し、オーバーレイタップで閉じる
  - サイドバー内のナビ項目（`NavLink`）をタップすると、画面遷移と同時にサイドバーを閉じる（`open`を`false`に）
  - ログアウトボタン・フィードバックボタン・ビルド時刻表示など、既存のサイドバー内要素はそのまま維持する（省略しない）

### 2. ダッシュボード（`Dashboard.tsx`）

- **`md`以上（現状維持）**: KPIカード4枚を横並び（`repeat(4, 1fr)`）、案件リスト2枚（進行中/未受注）を横並び（`1fr 1fr`）
- **`md`未満**:
  - KPIカード4枚を2列×2行（`repeat(2, 1fr)`）に変更
  - 案件リスト2枚（進行中/未受注）を縦に1列積みへ変更
  - 稼働予定日数の帯・クイックアクションボタン・得意先数フッターは変更しない（そのまま縦幅いっぱいに収まる想定）
- 情報の間引きは行わない（KPI・案件リストとも表示項目は`md`以上と同じ）。列数のみを変更する

### 3. 案件一覧（`ProjectList.tsx`）

- **`md`以上（現状維持）**: 現状の7列DataTable（案件コード/案件名/得意先/ステータス/開始日/納期/工数目安+操作列）
- **`md`未満**: DataTableの代わりに、簡素なリスト行を1件1行で表示する
  - 表示項目（2行程度にまとめる）:
    - 1行目: 案件名（太字）＋ 案件コード（`#` monospace、小さめグレー）
    - 2行目: 得意先名 ＋ ステータスバッジ（既存の`statusColor`/`statusLabel`を流用） ＋ 納期（既存の`getDeadlineTier`/`deadlineTierClassName`/`deadlineTierIcon`を流用）
  - 行全体をタップすると案件詳細（`/projects/{id}`）へ遷移する（既存の`onRowClick`と同じ遷移先）
  - **編集・削除ボタンは簡素リストには置かない**（行タップ→詳細画面で編集・削除を行う。一覧上のボタン省略により2行に収める。開始日・工数目安は詳細画面で確認する）
  - 検索input・「＋新規登録」ボタン・ページネーションは`md`未満でも同じ挙動を維持する（横幅いっぱいに広がるようレイアウト調整は可）
- タップ領域は1行あたり最低44px確保する（アクセシビリティ最低限）

### 4. 得意先一覧（`CustomerList.tsx`）

- **`md`以上（現状維持）**: 現状の4列DataTable（コード/得意先名/電話/住所+操作列）
- **`md`未満**: DataTableの代わりに、簡素なリスト行を1件1行で表示する
  - 表示項目（2行程度にまとめる）:
    - 1行目: 得意先名（太字） ＋ コード（小さめグレー）
    - 2行目: 電話番号（`tel:`リンク、タップで発信。電話番号なしなら非表示） ＋ 住所（1行、はみ出す場合は`text-overflow: ellipsis`で省略）
  - 行タップ（電話番号リンク以外の領域）で得意先詳細（`/customers/{id}`）へ遷移する
  - 電話番号リンクをタップした場合は行クリックの詳細遷移を発火させない（`stopPropagation`で行タップと分離する。既存DataTableの`stopRowClick`と同じ考え方）
  - **編集・削除ボタンは簡素リストには置かない**（行タップ→詳細画面で編集・削除を行う）
  - 検索input・「＋新規登録」ボタン・ページネーションは`md`未満でも同じ挙動を維持する
- タップ領域は1行あたり最低44px確保する

## TDD必須

- `AppLayout.tsx`: ハンバーガーボタンクリックでサイドバーの開閉状態（`open`）が切り替わること、ナビ項目クリックで`open`が`false`に戻ることをRTLでテストする
- `ProjectList.tsx` / `CustomerList.tsx`: 簡素リスト行が`md:hidden`相当のクラスを持ち、DataTableラッパーが`hidden md:block`相当のクラスを持つこと（両方がDOMに存在し、CSSクラスで出し分けていることを確認する）をテストする
- `ProjectList.tsx`: 簡素リスト行をクリックすると案件詳細への`navigate`が呼ばれることをテストする
- `CustomerList.tsx`: 簡素リスト行をクリックすると得意先詳細への`navigate`が呼ばれること、電話番号リンクをクリックしたときは`navigate`が呼ばれない（伝播が止まる）ことをテストする
- `Dashboard.tsx`: 既存のテスト（`Dashboard.estimatedHours.test.tsx`）が壊れないことを確認する（グリッド列数変更はスタイルのみのため、既存アサーションへの影響有無を確認する）

## 受け入れ条件

1. `md`未満でサイドバーが非表示になり、画面上部にハンバーガーボタンが表示される。ボタンタップでサイドバーがオーバーレイ表示され、ナビ項目タップまたはオーバーレイタップで閉じる
2. `md`以上ではサイドバーが常時表示され、ハンバーガーボタンは表示されない（現状の見た目・動作を変更しない）
3. `md`未満でダッシュボードのKPIカードが2列×2行、案件リスト（進行中/未受注）が縦1列になる。`md`以上は現状の4列/2列レイアウトのまま
4. `md`未満で案件一覧がDataTableではなく簡素なリスト行（案件名+コード、得意先名、ステータスバッジ、納期）で表示され、行タップで案件詳細へ遷移する。検索・新規登録・ページネーションは従来通り機能する。`md`以上は現状のDataTableのまま
5. `md`未満で得意先一覧がDataTableではなく簡素なリスト行（コード+得意先名、電話[タップで発信]、住所）で表示され、行タップで得意先詳細へ遷移する。電話番号タップでは詳細遷移せず発信リンクが機能する。`md`以上は現状のDataTableのまま
6. `DataTable.tsx`本体・新規の共通フック/共通コンポーネントファイルを追加していない
7. 既存のテスト・ビルド・回帰スイートが通る

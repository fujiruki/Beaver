# R-0091 / R-0092: 案件一覧の検索拡張・状態保持・複合ソート

## 背景

R-0080フィードバック（id=10、2026-08-05 05:01）より。

> 案件一覧の画面で、ステータス順＋納期順とか、２つ組み合わせて並べ替える方法って作れる？それと、再読み込みしてもその状態が保存されてると良いな。それと、案件一覧での検索のキーワードを得意先も検索対象にいれてほしい

指揮役からの確認（2026-08-05）: 複合ソートの操作方法は「Shift+クリックで第2ソートキーを追加」を採用する。

## R-0091: 案件一覧の検索対象拡張・状態のURL保持

### 検索対象拡張
`api/routes/projects.php` の一覧検索（246-249行目付近、現状 `p.name LIKE ?` のみ）を、`p.project_code` / `p.name` / `c.name`（得意先名、既にLEFT JOIN済み）を対象に拡張する。`api/search_helpers.php` の `buildMultiColumnSearchClause`（R-0090で拡張したかな正規化・AND対応版）をそのまま使う。

### 状態のURL保持
`frontend/src/pages/ProjectList.tsx` は現状 `useSearchParams` を`customer_id`の初期値取得にのみ使っている。ページ番号・ソートキー/方向・検索キーワードも `useSearchParams`（`setSearchParams`）でURLクエリに反映し、リロードしても一覧の状態（ページ・ソート・検索語）が復元されるようにする。

## R-0092: 案件一覧の複合ソート（Shift+クリックで第2ソートキー追加）

### DataTable拡張（`frontend/src/components/DataTable.tsx`）

共有コンポーネントのため、**既存の単一ソート方式は完全に後方互換を保つ**（他画面: 得意先一覧・建具台帳一覧・伝票一覧・請求書一覧は無変更で動作すること）。

- 新しいオプトインprop（例: `multiSort?: boolean`）を追加。`true`の場合のみ複数ソートキーを保持する内部状態に切り替える
- 通常クリック: そのカラム単独でソート（複合ソートをリセットし、単一キーに戻す。既存動作と同じ）
- Shift+クリック: 既存のソートキー列に、クリックしたカラムを「第2（第3…）ソートキー」として追加する（同じキーを再度Shift+クリックした場合は昇順/降順をトグル、既存キー配列から一旦除去して末尾に付け直す等、シンプルな実装でよい）
- ヘッダーに現在のソート順位を示す（例: `▲1` `▲2` のように小さく番号を添える）
- `onSortChange`のコールバックシグネチャを、`multiSort`時は複数キー配列を渡せる形に拡張する（既存の単一ソート利用側の型・呼び出しは変更しないこと。後方互換を最優先する）

### バックエンドのソート拡張（`api/routes/list_helpers.php`の`resolveSortClause`、`api/routes/projects.php`）

- `resolveSortClause`（または新関数）が、`$_GET['sort']`/`$_GET['order']`をカンマ区切りの複数値として解釈できるようにする（例: `sort=status,delivery_date&order=asc,asc`）。カンマが無い場合は既存の単一カラム動作と完全に同じ結果になること（後方互換）
- `api/routes/projects.php`の案件一覧ソートで、`status`と`delivery_date`を含む複数カラムの複合`ORDER BY`を組み立てられるようにする

## 受け入れ条件

1. 案件一覧の検索キーワードで、得意先名でもヒットすること（かな正規化・空白区切りAND検索も効くこと、R-0090のヘルパーを流用するため）
2. 案件一覧でページ・ソート・検索語を変更後にリロードしても、その状態が復元されること
3. 案件一覧のステータス列をクリック→Shift押しながら納期列をクリックで、ステータス優先・納期を第2キーとした複合ソートになること
4. 他の一覧画面（得意先・建具台帳・伝票・請求書）のソート・検索が今まで通り動作すること（DataTableの後方互換性、既存テストで担保）
5. 新規・変更箇所にTDDでテストを追加すること
6. `npm run build`が通ること、`bash .claude/regression-suite.sh`がexit 0であること

# R-0249 「行を挿入」を連打すると並べ替えの保存が 400 になる

対象: `frontend/src/pages/VoucherEdit.tsx` の `handleInsertLine`・`saveLineOrder`（▲▼の `handleMoveUp`/`handleMoveDown` も同じ保存を使う）

## 原因
- `handleInsertLine` は、押した時点の明細（`currentLines = getValues('lines')`）を覚え、行の作成（POST）が終わったあとの `.then` で、その古い一覧に新しい行を差し込んで `replace` し、`saveLineOrder` に渡している。
- 連打すると、2回目以降は「前の回で作った行がまだ入っていない一覧」で並べ替えを送る。サーバーの `line-order` は伝票の行と `line_ids` が過不足なく一致しないと 400 を返すので、失敗する。画面の一覧も、前の回の行が一時的に消える。
- `saveLineOrder` は `line_ids` を呼んだ時点で作って書き込みの列（`enqueueVoucherWrite`）に積むため、列の順番が来たときには古い並びになっていることがある。

## 決まり
1. 「行を挿入」を押したときは、**選んでいる行の id**（＝新しい行を入れる目印）を覚える。位置の番号は覚えない。
2. 行の作成が終わったら、**その時点の明細**（`getValues('lines')`）に、目印の行の上へ新しい行を差し込む。目印の行が消えていれば末尾に入れる。`line_no` を 1 から振り直し、新しい行を選ぶ。
3. 並べ替えの保存は、書き込みの列で**順番が来たときに**、その時点の明細の id から `line_ids` を作る（積んだときの並びを持ち越さない）。▲▼も同じ。
4. 連打しても、押した回数だけ空の行が入り、どの `line-order` も 400 にならない。

## 受け入れ条件
- 保存済みの伝票（3行）で2行目を選び「行を挿入」を素早く3回押す → POST 3回、`line-order` はどれも 200（モックのサーバーは line_ids が伝票の行と過不足なく一致しないと 400 を返すようにする）、最後は合計6行で、元の1行目が先頭、元の2・3行目が最後の2行、その間に新しい空の行が3行入る（どの新しい行も、押した時点で選んでいた行の上に入る）。
- ▲を素早く2回押しても、どの `line-order` も 200。

# R-0220: 案件の予定（見積・見積依頼など）を段取りの画面に出す

- 状態: 本番反映済み（2026-10-29、release/r0220＝0872979、migration 040適用）。ブラウザでの確認は未
- 要望の原文: `docs/requests_log.md` の R-0220
- デザイン: `docs/design/R-0220_dandori_multi_schedule_mock.html` の**案A（1行のまま重ねる）**（晴樹さん選択）
- 関係する仕様: R-0111（段取りボード）、R-0146（シームレススクロール）、R-0218（右クリックメニュー）、R-0219（左スクロール）

## 目的

案件を立てた時点で「見積をいつまでにやる」「見積依頼をいつ送る」「製作はこのあたり」と、1つの案件に複数の時期がある。これを段取りの画面に出し、見積などのやることも段取りの画面で確かめられるようにする。Youkan のような細かい作業の分解はしない（R-0111 の「案件単位の粗い粒度」を守る）。

## 晴樹さんの決定（2026-10-29）

1. 見せ方は案A
2. 「1日の稼働案件数」に見積を数えない（製作と取付だけを数える）
3. 予定の種類に「材料発注」「外注依頼」を足す

## データ

### 予定の種類

| 種類 | 描き方 | 稼働数に数える |
|:--|:--|:--|
| 見積 | 細い紺 | 数えない |
| 見積依頼 | 細い紺 | 数えない |
| 現調 | 細い紺 | 数えない |
| 打合せ | 細い紺 | 数えない |
| 材料発注 | 細い紺 | 数えない |
| 外注依頼 | 細い紺 | 数えない |
| 取付 | 太いバー（製作と同じ高さ、濃い青緑 `#24646f`） | 数える |
| その他 | 細い紺 | 数えない |

- 種類の一覧はフロントの1か所に定数で持つ（マスタ表は作らない）。DB には文字列で保存する
- 「製作」は新しい表に入れない。今の段取りのバー（`projects.start_date` と工数）がそのまま「製作」の予定である

### 新しい表 `project_schedules`（migration 040）

| 列 | 型 | 内容 |
|:--|:--|:--|
| id | INTEGER PK | |
| project_id | INTEGER NOT NULL | `projects.id`。案件を消したら予定も消す（論理削除の案件の予定は返さない） |
| kind | TEXT NOT NULL | 上の種類のどれか。API で一覧にない値は 422 |
| start_date | DATE NULL | 空なら「期限だけ」の予定 |
| end_date | DATE NOT NULL | 期間の終わり、または期限 |
| memo | TEXT NOT NULL DEFAULT '' | 1行メモ |
| done | INTEGER NOT NULL DEFAULT 0 | 済 |
| created_at / updated_at | DATETIME | |

- `start_date > end_date` は 422
- Access とは同期しない。予定を書いても `projects.updated_at` は進めない（`/sync/changes` に影響させない）

### API

| メソッド | パス | 内容 |
|:--|:--|:--|
| GET | `/project-schedules` | 全案件の予定（論理削除の案件を除く）。段取りの画面用 |
| GET | `/projects/{id}/schedules` | その案件の予定 |
| POST | `/projects/{id}/schedules` | 追加 |
| PUT | `/project-schedules/{id}` | 部分更新（kind, start_date, end_date, memo, done） |
| DELETE | `/project-schedules/{id}` | 削除（物理削除） |

認証は今の通常 API と同じ（同期トークンだけでは通らない）。

## 画面

### 案件の画面: 「予定」の表

- 案件の画面に「予定」の表を置く。列: 種類（選択）・開始・終了/期限・メモ・済
- 表の最後にいつも空の行を1行出す。種類を選ぶか終了/期限を入れた時点でその行を作り、下にまた空の行が出る（R-0200(B) と同じ操作感）。終了/期限が空のままの行は保存しない
- 行ごとに削除ボタン
- 製作は表に入れず、表の上に「製作: 開始日・工数は上の欄」と1行で示す
- 日付は `<input type="date">`。数値・金額は無いので右寄せの規則は関係しない

### 段取りの画面（横スクロールモード）

- 1行の高さは今のまま。行の上の帯（高さ約8px）に、細い紺 `#4a5fa8` で見積などの期間を描き、右に種類名を小さく出す。期限だけの予定は ◆ と種類名
- 取付は製作と同じ太さ・位置のバーで描く
- 済の予定は薄い色 `#b9c0d8`
- 製作のバー・納期線・ドラッグ・納期超過の斜線は今のまま
- 予定のバーと◆は左右にドラッグして日付を動かせる（1日スナップ、ドロップ時に PUT。期間は開始と終了を同じ日数だけ動かす）。既存の `useDayDrag` を使う
- 予定のバー・◆にマウスを乗せると「種類 期間 メモ」を title で出す
- 右クリックメニュー（R-0218）に「予定を追加」を足す。押すと小さな入力画面（種類・開始・終了/期限・メモ）を開く
- **開始日が無い案件でも、済でない予定が1件以上あれば行を出す**（製作のバーは無し）。ヘッダーの「開始日未設定 n件」は、行に出なかった案件だけを数える
- 完了・キャンセル系で隠している案件は、予定も隠す（今のトグルに従う）
- 「1日の稼働案件数」と空きマーカーは、製作のバーに加えて取付の予定（済でないもの）を数える。同じ案件の製作と取付が同じ日に重なっても1件と数える

### 段取りの画面: 「やること」

- ツールバーに「やること」の表示切り替えを置き、右側に一覧を出す（表示状態は localStorage、既存のキーの命名に合わせる）
- 済でない予定を、終了/期限の日付順に並べる。行: チェック・日付（M/D）・種類（メモ）・案件名
- 期限が今日より前で済でないものは日付を赤
- チェックで `done=1` にする。「済も表示」のチェックで済も並べる
- 案件名をクリックすると、今のダブルクリックと同じく案件を開く

### 対象外（v1）

- 折り返しモードには予定を出さない（今のまま）
- 段取りの空いている所をドラッグして予定を作る操作（デザイン案に書いたもの）は v1 では作らない。右クリックの「予定を追加」で入れる
- Youkan・Access との連携

## 受け入れ条件

1. 案件の画面で予定を追加・変更・削除でき、末尾の空行に入れると行が増える
2. 段取りの画面で、見積などは行の上の細い帯、取付は太いバー、期限だけは◆で出る。済は薄い色
3. 開始日の無い案件でも、済でない予定があれば段取りに行が出る
4. 予定をドラッグすると日付が変わり、保存される
5. 稼働数は製作と取付だけを数え、見積などは数えない
6. 「やること」に済でない予定が日付順に出て、チェックで済になる
7. 予定を書いても `projects.updated_at` は変わらず、`/sync/changes` の件数も変わらない
8. 回帰スイート（vitest＋PHPテスト）が全部通る

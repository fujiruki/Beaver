# R-0168: 伝票画面を離れるときは保存の結果を待ち、409や失敗なら離れない

- 状態: 確定（2026-10-10）
- 起点: dodai-backのR-0166 beta確認（C）で藤田晴樹さんが見つけた問題（dodai-back経由）
- 関連: R-0164（ヘッダー自動保存・離脱警告）、R-0166（楽観的ロック）

## 要望の原文（dodai-back経由）

> 手順: 開きっぱなしの画面で摘要を編集 →「閉じる」ボタン →「保存していませんが保存しますか？」で「保存する」を押す。
> 結果: PUT /vouchers/5809 が 409 になったのに、何も表示されないまま画面が閉じた。入力した内容が黙って消えた形です。
> 期待: 閉じる・離れるときの保存で 409 stale_voucher になったら、画面を閉じない。項目変更時の自動保存と同じく「ほかで更新されています（最終更新: …）」と「再読み込み」を出し、入力中の値は残す。ほかの「離れる」経路（ブラウザの戻る、別ページへの移動、タブを閉じる）でも同じにしてほしいです。

## 原因

入力中に「閉じる」を押すと、blurでヘッダーの自動保存が始まる。保存が終わる前に離脱ガード（`NavigationBlocker`）が「保存されていない変更があります。破棄して移動しますか？」を出し、OKで即座に移動する。409は移動後に返るため、画面には何も出ない。

## 仕様

画面内の移動（「閉じる」、ブラウザの戻る・進む、メニューなどからの別ページへの移動）で離脱ガードが働いたとき:

1. まず確認ダイアログを出さずに、未保存のヘッダーがあれば保存を始め、実行中の保存（ヘッダー・明細）がすべて終わるのを待つ
2. 結果ごとの動き:
   - **すべて成功し、未保存の変更が残っていない**: 確認を出さずにそのまま移動する
   - **409 stale_voucher になった**: 移動を取りやめる。R-0166と同じく「ほかで更新されています（最終更新: …）」と「再読み込み」を出し、入力中の値は画面に残す。ダイアログは出さない
   - **保存に失敗した（409以外）**: 移動を取りやめ、既存の「保存に失敗しました（再試行）」を表示する。ダイアログは出さない
   - **必須項目が空で保存できない（新規伝票の未作成を含む）**: 今の確認ダイアログを出す。OKで破棄して移動、キャンセルでとどまる
3. 待っている間に同じ移動操作を重ねても、二重に保存しない

タブを閉じる・再読み込み（`beforeunload`）:
- ブラウザの仕様上、保存の完了を待てない。保存中・未保存・失敗・stale のどれかなら、今と同じくブラウザ標準の警告を出す（stale のときも出すことを追加）

## 受け入れ条件（vitest）

1. 摘要を変えてすぐ「閉じる」→ PUT が成功 → ダイアログなしで `/vouchers` へ移動する
2. 摘要を変えてすぐ「閉じる」→ PUT が 409 stale_voucher → 移動しない。stale の表示と「再読み込み」が出る。摘要の入力値が残っている。`window.confirm` は呼ばれない
3. 摘要を変えてすぐ「閉じる」→ PUT が 500 → 移動しない。保存失敗の表示が出る。`window.confirm` は呼ばれない
4. 必須項目（得意先）を空にして「閉じる」→ `window.confirm` が呼ばれ、OKで移動、キャンセルでとどまる
5. stale の状態で `beforeunload` を発火すると `preventDefault` される
6. 既存のR-0164・R-0166のテストは期待値を変えずに通る。ただし次の1件は本仕様でR-0164の動きを置き換えるため、期待値を本仕様に合わせて改める（2026-10-10 指揮役が追記）
   - `VoucherEdit.r0164.test.tsx`「保存中・失敗・未保存では閉じる時に確認し、留まるを選ぶと残る」: 保存中に「閉じる」を押したときは確認ダイアログを出さず、保存の完了を待つ（`window.confirm` は呼ばれず、画面にとどまったまま）。保存が終わったら仕様2のとおり移動する。テスト名も本仕様に合わせて改める
   - R-0164仕様書の「保存中・保存に失敗したまま離れようとしたら確認を出す」は、画面内の移動については本仕様で置き換える（必須項目が空のとき、およびタブを閉じる・再読み込みの警告は残る）

## 追加仕様（2026-10-10、dodai-back経由・晴樹さんのスクリーンショットより）

### 要望の原文（dodai-back経由）

> 晴樹さんが E02046（5809）を開き直したところ、開いた直後から「ほかで更新されています」が出た。摘要の欄が、実データの「テスト見積深田様２」ではなく、前回保存できなかった古い入力の「テスト見積深田様」になっていた。画面の下に生のエラー文がそのまま表示された: 「保存に失敗しました: Error: API error 409: {"error":"stale_voucher",…（JSON 全体）」。
> (a) 開き直したときは、サーバーの最新値でフォームを作ってください。保存できなかった下書きを黙って復元して自動保存しないでください。
> (b) 生の JSON を利用者に見せないでください。409 stale_voucher は、上部の案内だけで十分です。

### 原因（指揮役の確認）

Beaverに下書きを保存する仕組みはない。伝票詳細のクエリ（`['vouchers', id]`）がアプリ全体の `staleTime` 3分でキャッシュされ、開き直したときにサーバーから取り直さず古いキャッシュ（Access変更前の値と古い `updated_at`）でフォームを作っていた。その古い値で自動保存が走り409になった。

### 仕様

7. 伝票編集画面を開いたとき（開き直しを含む）は、必ずサーバーから伝票を取り直し、その最新値でフォームと `expected_updated_at` を作る。取り直しが終わるまでは自動保存を送らない（キャッシュの古い値で送らない）
8. 409 `stale_voucher` は上部の案内（R-0166）だけで知らせる。画面下の「保存に失敗しました」や明細の保存エラーの表示には出さない
9. それ以外の保存エラーも、APIの生のJSONを画面に出さない。サーバーの `error` が文字列ならそれを、なければ「保存に失敗しました（HTTP 500）」のように短く表示する

### 受け入れ条件（追加）

7. キャッシュに古い伝票（摘要A、updated_at T1）がある状態で編集画面を開き、サーバーは摘要B・updated_at T2 を返す → フォームの摘要はB。開いただけではPUTが送られない。その後に項目を変えるとPUTの `expected_updated_at` はT2
8. PUTが409 stale_voucherのとき、画面のどこにも `{"error"` や `API error 409` の文字列が出ない
9. PUTが500 `{"error":"db locked"}` のとき、表示は「保存に失敗しました: db locked」相当で、生のJSONが出ない

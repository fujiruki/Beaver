# R-0103: 表の列幅ドラッグ時、総幅も一緒に縮む/広がるようにする

## 背景
R-0080フィードバック（id=16、2026-08-06 10:18）より。

> 表の列幅調整が希望通りの動きじゃない。列の区切り線をドラッグする操作自体は良い。でも、ドラッグしたら、その掴んだ線の左の列幅だけが縮んでほしい、そうしたら、表の総幅も縮むことになるよね、現状は、幅を縮めると、他列の幅が増したりして表の総幅が一定のままになるような挙動をしている。それはやめてほしい。ドラッグしている境界線の左の列が縮み、それより右の列は追従して移動はすることになるけど列幅は変化しない。

## 原因
`frontend/src/components/DataTable.tsx`のテーブル要素（312行目付近）が
```
<table style={{ width: 'max-content', minWidth: '100%', borderCollapse: 'collapse', tableLayout: 'fixed' }}>
```
となっており、`minWidth: '100%'`が指定されているため、ドラッグである列を縮めて列幅の合計が親要素の100%未満になっても、ブラウザがテーブル全体の幅を100%まで引き伸ばし、`table-layout: fixed`の仕様により他の列に余った幅が比例配分されてしまう。結果として「1列だけ縮めたつもりが他列が広がって総幅は変わらない」という、要望とは逆の挙動になっている。

## 修正方針
`minWidth: '100%'`を削除する。`width: 'max-content'`のみにすることで、テーブルの総幅は各列の明示幅の合計（＝ユーザーがドラッグ操作で作った合計）にそのまま従うようになり、列を縮めれば総幅も縮む・広げれば総幅も広がる、という要望通りの挙動になる。

外側の`<div style={{ overflowX: 'auto', width: '100%' }}>`（280行目付近）は変更不要（テーブルが親要素より狭くなった場合は単に左寄せで表示され、広くなった場合は横スクロールになる、という既存のスクロール処理はそのまま活きる）。

## 確認してほしいこと
- 他の一覧画面（得意先・案件・建具台帳・伝票・請求書）で、列幅未調整（初期状態）の見た目が大きく崩れないこと（多くの列に`width`のデフォルト値が設定されている場合は、初期状態ではほぼ変化が無いはずだが、念のため確認する）
- 列幅リサイズの既存テスト（`DataTable.test.tsx`等）が引き続き通ること。無ければ「1列をドラッグで縮めると、他の列の幅は変化せずテーブル総幅が縮む」ことを検証するテストを追加する

## 受け入れ条件
1. 列の区切り線をドラッグすると、その左側の列の幅だけが変化する
2. テーブル全体の幅が、列幅の変化に応じて縮む/広がる（他列が自動的に広がって総幅を一定に保とうとしない）
3. 既存の列幅・列順序の保存（localStorage）機能は壊れない

# R-0257 保存が「ほかで更新されています」で断られたとき、この画面の内容で上書きできるようにする

原文は requests_log の R-0257。経緯: 2026-11-10、晴樹さんが同じ伝票 E03991 を2つのタブで開いていて、片方が保存したため、もう片方の入力がすべて 409 stale_voucher で断られた。選べるのが「再読み込み（この画面の入力を捨てる）」だけだったので、入力を失いかけた。

## 画面（`pages/VoucherEdit.tsx` の stale の警告）
- 今の文言と「再読み込み」は残し、その横に「この画面の内容で上書き」ボタンを足す（type="button"）。
- 「この画面の内容で上書き」の下に、小さく「もう一方の画面で保存した内容は、この画面の内容に置き換わります」と出す。ブラウザの confirm は使わない。
- 押したら:
  1. GET /vouchers/{id} で最新の伝票を取り、その updated_at を expected_updated_at にする。
  2. 画面の見出し（今の見出しの保存と同じ項目）を PUT する。
  3. 画面の明細を、上から順に1行ずつ PUT /vouchers/{id}/lines/{lineId} する。送る項目は、明細の保存（saveLineToDb と台帳をひもづけたときの保存）で送っている項目すべて（取付場所・品名・種別・数量・労務単価・売値・税区分・備考・原価 costs・売値 prices・tategu_item_id・cost_*）。各応答の voucher_updated_at を次の expected_updated_at に使う。
  4. 明細の順番を、今の line-order で保存する（画面にある行だけ）。
  5. 全部成功したら stale を解き、保存の状態を「保存済」にして、伝票を取り直す。
- 注意: 台帳をひもづけている行は、サーバーが労務単価を台帳の値に戻すことがあるので、tategu_item_id を送ったあとに cost_labor_rate を送り直す（または同じ PUT で両方送り、応答の cost_labor_rate が画面の値と違えばもう一度送る）。2026-11-10 の E03991 の入れ直しで実際に起きた。
- 画面にない行（もう一方の画面で足された行）は消さずに残し、終わったあと「もう一方の画面で足された明細がN行あります」と出す。
- 画面にあってサーバーにない行（もう一方で消された行）は 404 になる。その行は飛ばし、終わったあと「もう一方の画面で消された明細がN行あり、上書きしませんでした」と出す。
- 途中で失敗したら止めて、どこまで保存できたかを出し、「この画面の内容で上書き」をもう一度押せるようにする。

## 受け入れ条件（vitest、サーバーはモック）
- stale の警告に「この画面の内容で上書き」が出て、押すと最新の updated_at を使って見出し→明細→順番の順に保存し、stale が解ける。
- 台帳をひもづけた行で、応答の労務単価が画面と違えば送り直す。
- 404 の行は飛ばして続け、件数を出す。
- 押しても、ブラウザの confirm／alert は出ない。
- ブラウザで: 同じ伝票を2つのタブで開き、片方で保存→もう片方で入力→警告→「この画面の内容で上書き」→読み直すと、あとのタブの内容になっている（beta で）。

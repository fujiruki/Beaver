# R-0182: 存在しない伝票の画面で「閉じる」と「保存」が繰り返しになる

- 受付: 2026-10-17 藤田晴樹さんがBeaver_betaの受入確認（S4）で報告（dodai-back経由）
- 状態: 仕様確定（原因の細部はテストで再現してから確定する）

## 報告

見積伝票を編集して「保存」→「閉じる」→「保存」→「閉じる」と押すと、「閉じる」を押しても閉じずに「保存」ボタンが出る → 「保存」を押すと保存ボタンが消える → 「閉じる」でまた保存ボタンが出る、の繰り返しになった。コンソールに`/contents/Beaver_beta/api/vouchers/11709`の404が2回出ていた。

## 指揮役の調査（2026-10-17）

- Beaver_betaに伝票id 11709は無い（最大11707）。11709はrc1の前のbetaにあったテスト用の伝票E03981のid。rc1〜rc4でbetaのDBを本番の写しに入れ替えたため消えた。画面は入れ替え前に開いたタブか、ブックマーク・履歴のURLの可能性が高い
- 入れ替え後はAccessの全件再pushで伝票が作り直され、id 5811〜11707が新しく振られた。このため入れ替え前のidが、別の伝票を指していることがある（beta特有。本番ではDBを入れ替えないので起きない）
- 伝票画面（`VoucherEdit.tsx`）は`GET /vouchers/{id}`が404でもエラー表示をせず、空のフォームを編集できる状態で出す。保存は`PUT /vouchers/{id}`→404になる。離れるときの保存（R-0168の`beforeLeave`）が失敗して離れられず、R-0172の保存状態表示の「再試行」などが出る、という流れが疑わしい
- 404で保存に失敗したのに「保存済み」に見える経路があれば、入力が消えるので最優先で塞ぐ

## 仕様

1. 伝票画面で`GET /vouchers/{id}`が404のときは、フォームを出さず「この伝票は見つかりません（削除されたか、データが入れ替わりました）」と「伝票一覧へ」のリンクだけを出す。書き込みは一切送らない。離脱確認も出さない
2. 伝票の書き込み（ヘッダー・明細・原価再取得・取消・下書きに戻す）が404で失敗したときは、保存済みに見せない。保存状態は「保存に失敗しました: この伝票は見つかりません」とし、「再試行」は出さず「伝票一覧へ」を出す。離脱確認は出さずに離れられる（保存先が無いため）。入力は画面に残す
3. 404以外の失敗のときの動き（R-0166・R-0168・R-0172）は変えない。ただし、テストで再現したループの原因が404以外にもあれば、同じく「保存に失敗したのに保存済みに見える」ことが無いように直す
4. 得意先詳細（R-0167・R-0180）にも同じ穴（存在しないidで空フォーム）があれば、同じ扱い（「この得意先は見つかりません」）にする

## 受け入れ条件（テスト）

vitest:

1. `GET /vouchers/{id}`が404なら「この伝票は見つかりません」と「伝票一覧へ」が出て、フォームと保存ボタンが無い。`PUT`は送られない
2. 報告の手順（編集→保存→閉じる→保存→閉じる）を、`PUT`が404を返すモックで再現するテスト。保存状態が「保存しました」にならず、「閉じる」で離れられ、ループにならない
3. 書き込みが404のとき「再試行」が出ず「伝票一覧へ」が出る
4. 404以外（500・409 stale_voucher）の既存の動きのテスト（R-0166・R-0168・R-0172）が通る
5. 得意先詳細も、存在しないidなら「この得意先は見つかりません」が出てフォームが出ない
6. 既存のテストと回帰スイートが通る

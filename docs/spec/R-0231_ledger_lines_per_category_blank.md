# R-0231: 製品台帳の材料費・工程の表を詰め、区分ごとにいつも空の行を出す

- 状態: 仕様化済み（2026-11-02）
- 要望の原文: `docs/requests_log.md` の R-0231
- 対象: `frontend/src/components/TateguLineItemsPanel.tsx`（製品台帳の画面 `pages/TateguItemDetail.tsx` と、伝票から開く `components/voucher/ProductLedgerModal.tsx` の両方で使う）。API・DB は変えない
- 見た目の決まり: `docs/design/DESIGN_SYSTEM.md`（共通 CSS `beaver-ui.css`、見本帳 `docs/design/ui-kit.html`）。新しい見た目は作らず、決まりの部品を当てる
- 検証の強さ: L2（保存に関わるので操作の確認 G8b は省かない）

## 今の作り（事実）

- 材料費明細: 区分ごとの合計を角丸のカード4枚（本体合計・金物合計・ガラス合計・材料費合計）で出し、その下に表。行の間・欄の間に余白があり、入力欄はそれぞれ角丸の枠
- 空の行は表の最後に1行だけ（区分は空の行のセレクトで選ぶ）。工程の表も同じ作り

## 仕様

### 1. 区分ごとの空の行（材料費・工程の両方）
- 行は区分ごとにまとめて並べる。区分の順は集計区分マスタの順（材料費: 本体・金物・ガラス…、工程: 工場・現場…）。同じ区分の中は今の順のまま
- 各区分のまとまりの最後に、その区分の空の行をいつも1行出す。空の行の区分は決まっていて、区分のセレクトは出さない（区分名を薄い字で出す）
- 空の行に入力されたら（名前・数量・単価・時間のどれか）、その区分の行として加わり、そのすぐ下にまた同じ区分の空の行が出る
  - 例: 本体・金物・ガラスの空の行 → 本体に入力 → 本体・本体（空）・金物（空）・ガラス（空） → ガラスに入力 → 本体・本体（空）・金物（空）・ガラス・ガラス（空）
- 入力済みの行の区分は今どおりセレクトで変えられる。変えたら、その行は変えた先の区分のまとまりへ移る（入力中は動かさず、行から出たときに移す。R-0225 と同じ考え方）
- 保存は今の台帳の保存のしかたのまま。行の並び（`sort_order` など）は区分ごとにまとめた順で保存してよい
- 空の行は保存しない（今と同じ）

### 2. 表を詰める（DESIGN_SYSTEM.md の決まりを当てる）
- 表は `bv-table`、入力欄はマスそのもの（`bv-control`。マスの中に枠付きの欄を置かない）、角丸なし、行の間・欄の間の余白なし、列見出しは沈んだ色、数値・金額は右寄せ・3桁区切り・¥
- 区分ごとの合計は、角丸のカードをやめ、表の上の1行のマス（表示だけ・`bv-readonly`、項目名が上）で並べる: 本体合計・金物合計・ガラス合計・材料費合計（材料費合計は太字のまま）。工程の合計も同じ形
- 空の行の区分名・プレースホルダは薄い字。入力済みの値は普通の濃さ
- 製品台帳の画面とモーダルの両方で、`bv-ui` の中に入るようにする（その外の古い部分に影響させない）

## 受け入れ条件（vitest）
1. 材料費の表に、行が無いとき 本体・金物・ガラスの空の行が1行ずつ、この順で出る
2. 本体の空の行の名前に入力すると、本体の行が加わり、その下に本体の空の行が出る（並び: 本体・本体（空）・金物（空）・ガラス（空））。続けてガラスに入力すると 本体・本体（空）・金物（空）・ガラス・ガラス（空）
3. 保存されるのは空でない行だけで、区分が正しい
4. 工程の表も区分ごとに空の行が出る
5. 既存のテスト・回帰スイートが全部通る（表の形が変わって前提が変わったテストは、確かめる中身を弱めずに直す）

## 見た目と操作の確認（指揮役、beta で）

- 製品台帳の画面と、伝票から開くモーダルの両方で、区分ごとの空の行に入力 → 行が加わる → 保存 → 開き直して残っている

# R-0147: 案件一覧にステータス全種類のフィルタボタンを追加

## 背景

本番フィードバック（`docs/requests.md` 旧§34、id=49、2026-09-11、`/projects`）:

> 「案件一覽の右側にステータスの全種類のボタンをつくり、クリックでフィルタリングできるようにしてほしい」

## 調査結果

バックエンド`GET /projects`（`api/routes/projects.php`）は既に`?status=`クエリパラメータでのフィルタに対応済み（377〜384行目付近）。ただし**バグを発見**: 一覧のデフォルトWHERE句が`WHERE p.status != "キャンセル"`固定になっており、`status=キャンセル`を明示的に指定した場合でも`AND p.status = 'キャンセル'`が追加されて`!= キャンセル AND = キャンセル`という矛盾条件になり、常に0件になる。ステータス種類は`project_statuses`マスタに8種（問い合わせ・見積済・受注済・進行中・納品済・請求済・完了・キャンセル、工程順）。

フロントエンド`ProjectList.tsx`は検索テキストボックス・得意先フィルタはあるが、ステータスによるフィルタUIが無い。

## 対応方針

### (A) バックエンドのバグ修正

`status`クエリパラメータが明示的に指定された場合は、既定の`p.status != "キャンセル"`除外を適用せず、指定されたstatus一致条件のみを使う（`status`未指定時は従来通り「キャンセル」を除外する既存動作を維持）。

### (B) フロントエンド: ステータスフィルタボタン

`ProjectList.tsx`の一覧右側（藤田晴樹さんの原文「右側に」の通り、既存のツールバー/検索欄の右側を想定）に、`project_statuses`マスタの全8種類＋「すべて」を工程順で並べたボタン群を追加する。クリックで`status`フィルタをON/OFFし、既存の`q`・`customer_id`と同様に`filters`オブジェクトへ組み込み、URLクエリ（`syncUrl`と同じ方式、`status`パラメータを追加）にも反映して再読み込み後も復元できるようにする。単一選択（同時に1ステータスのみ絞り込み、複数選択には対応しない、シンプルさ優先）。

## TDD

## 受け入れ条件

1. 案件一覧画面にステータス全種類（キャンセル含む）のフィルタボタンが表示され、クリックでそのステータスのみに絞り込まれる
2. 「すべて」で絞り込み解除（キャンセルを除く既存のデフォルト表示に戻る）
3. `status=キャンセル`で絞り込むとキャンセル案件が正しく表示される（現状のバグが解消される）
4. フィルタ状態がURLクエリに反映され、リロード後も復元される
5. 既存テスト・回帰スイートが通る

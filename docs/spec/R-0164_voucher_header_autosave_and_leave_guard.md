# R-0164: 伝票ヘッダーの自動保存と、未保存のまま離れるときの警告

- 要望: 2026-10-10 藤田晴樹さん（会話内で直接）
- 状態: 仕様確定

藤田晴樹さんの原文:

> beaverは伝票を書き換えて閉じたときに、保存しわすれてても警告がないね、おそろしい。どうなってたらユーザビリティとしてはいいのかな
>
> Cがいい

（C＝ヘッダーも自動保存にそろえ、保存中・保存失敗・未保存のまま離れるときだけ警告を出す案）

## 現状

伝票編集画面（`frontend/src/pages/VoucherEdit.tsx`）は保存のしかたが2通り混在している。

- 明細行: 入力欄からフォーカスが外れたときに1行ずつ自動保存
- ヘッダー（得意先・案件・伝票日付・ステータス・伝票種別・摘要・売上種別・納期・入力方式など）: 「保存」ボタンで保存

ヘッダーを書き換えて「閉じる」・他画面への移動・タブを閉じても警告が出ず、変更が黙って失われる。

## 仕様

### 1. ヘッダーの自動保存（既存の伝票）

- 文字の入力欄（摘要など）はフォーカスが外れたときに、選択欄・日付・切替ボタンは値を変えた時点で保存する
- 保存は既存の更新処理（`useUpdateVoucher`／`PUT /vouchers/{id}`）を使う。保存処理を複製しない
- 必須項目（得意先・伝票日付）が空など入力チェックに通らない間は保存しない。その項目の横に今と同じ形でエラーを出す
- 同じ伝票への保存が重ならないようにする（前の保存が終わってから次を送る。続けて変えた場合は最後の値が保存されればよい）
- 編集できない伝票（請求済み、Accessで請求済み、取消済み、売上に引用済みの見積）では自動保存しない（今の読み取り専用表示のまま）

### 2. 保存状態の表示

画面の見えるところ（下部の操作ボタンの並び）に、ヘッダーと明細を合わせた保存状態を出す。

- 保存中: 「保存中…」
- 保存済み: 「保存しました HH:MM」
- 失敗: 「保存に失敗しました」と理由、「再試行」ボタン
- 未保存（入力チェックで止まっている）: 「未保存の変更があります」

「保存」ボタンと「キャンセル」ボタンは、既存の伝票ではなくす（「閉じる」は残す）。

### 3. 新規作成の伝票

- 空の伝票ができないよう、最初の1回は今の「保存」ボタン（作成）で保存する。作成後は既存の伝票と同じく自動保存になる
- 作成前に離れようとしたとき、何か入力していれば警告を出す

### 4. 離れるときの警告

次のどれかの状態で、「閉じる」・アプリ内の画面移動・ブラウザのタブを閉じる・再読み込みをしようとしたら、確認を出す。

- ヘッダーまたは明細の保存中
- 保存に失敗したまま
- 入力チェックに通らず保存されていない変更がある
- 新規作成で、作成前に何か入力している

確認の文言: 「保存されていない変更があります。破棄して移動しますか？」（「破棄して移動」「このページに留まる」）。ブラウザのタブを閉じる・再読み込みはブラウザ標準の確認になる。

アプリ内の移動はReact Routerの仕組み（`useBlocker`など、使っているバージョンで使えるもの）で止める。

### 5. 変えないこと

- 明細行の保存のしかた（フォーカスが外れたときに1行ずつ）
- R-0154の取消ボタンの前に未保存の入力を保存する処理（自動保存になった後も、保存中の処理が終わるのを待ってから空判定する）
- Access同期のAPI

## 受け入れ条件（テスト・vitest）

1. 既存の伝票で摘要を変えてフォーカスを外すと、`PUT /vouchers/{id}`が1回送られ、「保存しました」が表示される
2. 得意先を選び直すと、その時点で保存される
3. 伝票日付を空にすると保存されず、「未保存の変更があります」が表示される
4. 保存がエラーになると「保存に失敗しました」と「再試行」が表示され、再試行で保存される
5. 保存中・保存失敗・未保存の状態で「閉じる」を押すと確認が出る。「このページに留まる」で画面に残る
6. すべて保存済みなら「閉じる」で確認なしに離れる
7. 編集できない伝票では保存が送られない
8. 新規作成画面では「保存」ボタンで作成でき、作成前に何か入力して離れようとすると確認が出る
9. 既存の伝票では「保存」「キャンセル」ボタンが表示されない
10. R-0154の取消（未保存の入力を保存してから空判定）と、既存のテスト・回帰スイートが通る

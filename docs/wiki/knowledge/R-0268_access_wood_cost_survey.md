## 1. 表の構造

木材原価の表は 3 つ。どれも BE（`dodaikun2026_be.accdb`）にあり、FE からはリンクテーブルで見る。表同士の外部キー制約や、外部キー列の索引は作られていない（索引は各表の主キーと、本体の建具№だけ。リレーションシップの定義そのものは照会していない）。つながりは「列の値が同じ」という約束で成り立つ。

### 製品台帳（tbl建具台帳_本体）とのつながり

`tbl建具台帳_本体` に「木材設定ID」（長整数）が足されていて、ここに値が入っている本体行が「木材原価の行」になる。

- 本体の列: ID、建具№、本体名(30)、本体数量、本体単価（長整数）、本体金額（通貨）、木材設定ID、並び順。
- 木材の行は 建具№ + 木材設定ID の組で 1 行。反映するたびに同じ組の行を更新し、無ければ挿入する。
- Beaver への同期（`Df_製品台帳同期.bas:420`）は、本体の行の木材設定IDが 0 でなければ `source='wood_calc'`、そうでなければ `manual` として送る。送るのは名前・数量・単価・金額だけで、木材設定・木材明細は Beaver へ行かない。Beaver の `tategu_item_cost_lines`（021 のマイグレーション）にも、材積や寸法を持つ列は無い。
- Beaver から Access への取り込みでは、木材設定ID 付きの本体行は消さず、取り込みもしない（`Df_製品台帳同期.bas:1120`）。木材の行は Access だけが直す。

## 2. 画面の動線

### 入口

`frm建具台帳` の `cmdWoodCost`（表示名「木材原価追加」。左8500・上100・幅2000・高さ400、TabIndex 20）が入口。ほかに入口は無い。

`cmdWoodCost_Click`（`frm建具台帳.frm` 内）の処理:
1. 本体サブフォーム `fsub建具台帳_本体` の現在行の「木材設定ID」を読む（エラーは無視、取れなければ 0）。
2. `OpenWoodCostForm 建具№, 木材設定ID` を呼ぶ。

`OpenWoodCostForm`（`Evt_木材原価.bas`）は、建具№ が 0 なら「先に製品を保存してください」を出して終了する。そうでなければ `frm木材原価計算` を `acDialog`（モーダル）で、OpenArgs に `"建具№,木材設定ID"` を渡して開く。

現在選んでいる本体行が木材行ならその設定が開き、そうでなければ新規設定になる。1 製品に木材設定が複数あるときは、本体サブフォームで目的の木材行を選んでからボタンを押す必要がある。

仕様書（`docs/spec/02_機能仕様.md:153`）は、木材設定がまだ無い製品では選択ダイアログ `frmWoodCopyDialog`（「新しく入力する」「他の製品からコピーする」）を挟むと書いている。しかし `cmdWoodCost_Click` はそれを呼ばず、`frmWoodCopyDialog` を開くコードはどこにも無い。フォームと `CopyWoodSettingFrom` は存在するが、画面から使えない。

### frm木材原価計算 の操作手順

1. 開く。`Form_Open` が `WoodForm_Open` を呼ぶ。OpenArgs が空なら「製品番号が指定されていません」を出して閉じる。製品№と木材設定IDを隠し欄へ入れ、設定IDがあれば部位名・樹種・立米単価を設定表から読む（樹種は名前で樹種表を引き、IDをコンボへ入れる）。
2. 開いた直後に 100ms のタイマーを 1 回動かし、その中で合計を計算する（`WoodForm_Timer`）。
3. 樹種をコンボで選ぶ（`cboJushu_AfterUpdate` → `WoodForm_JushuChange`）。立米単価欄へ樹種表の単価を入れ、その製品の木材明細の全行（木材設定が違う行も、建具№ が同じ行はすべて）の樹種IDをこの樹種に一括更新し、サブフォームを再読込して合計を再計算する。
4. 立米単価を手で書き換えると（`txtRyuubeiTanka_AfterUpdate`）、合計だけ再計算する。樹種表と違う単価を入れられる。実データにも 30・35・45・50・55・65 がある。
5. 明細を入れる。方法は 3 つ。
   - サブフォーム `fsubWoodDetail` のデータシートへ直接入力する。行追加時に建具№ と木材設定IDを親から自動で入れる（`Form_BeforeInsert`）。数値 5 欄の AfterUpdate ごとに `WoodForm_SubFieldChanged` が行を保存し、親の合計を再計算する。
   - 「テンプレート」ボタン（`WoodForm_Template`）。次の 12 行を追加する（項目名 見付×見込み×長さ 数 余裕）。
     框 45×30×2000 数2 余裕6 / 上桟 70×30×900 数1 余裕6 / 中桟 40×30×900 数1 余裕6 / 下桟 70×30×900 数1 余裕6 / 束 25×30×2000 数0 余裕6 / 格子タテ 18×15×2000 数0 余裕5 / 格子ヨコ 18×15×900 数0 余裕5 / 額 17×14×1500 数0 余裕4 / 隅丸 30×15×1500 数0 余裕4 / 組子縦 8×15×2000 数2 余裕3 / 組子横 8×15×900 数15 余裕3 / 特殊板 900×15×1000 数0 余裕0
     数が 0 の行は使わない行で、使う行だけ本数を入れ直す想定。
   - 「貼り付け」ボタン（`WoodForm_Paste` → `PasteWoodLines`）。クリップボードの TSV（項目名・見付・見込み・長さ・数・余裕の 6 列、タブ区切り）を取り込む。取り込み前に「既存の明細は削除されます」と確認し、その製品の木材明細を全部消して入れ直す（木材設定IDは 0 で入れる）。
6. 部位名を入れる。部位名が空のまま「反映」を押すと止められる。
7. 「反映」を押す（`cmdApply_Click` → `WoodForm_Apply`）。処理は下の「反映の処理」。
8. 「閉じる」（`DoCmd.Close`）。閉じるときに自動では反映しない。自動反映は `docs/requests.md` の R-110 として要望に挙がっているが、実装されていない。

### 計算式（`Ut_木材計算.bas`）

```
材積(m3) = (見付mm + 余裕mm) × (見込みmm + 余裕mm) × (長さmm + 100) ÷ 1,000,000,000
合計材積 = Σ（材積 × 数）                      -- 数が空は 0 扱い
木材原価 = CCur(合計材積 × 立米単価万円 × 10000)   -- 円
```

- 長さには固定で 100mm が足される。コードに埋め込みで、設定では変えられない。
- 余裕は見付と見込みの両方に足される。長さには足されない。
- 立米単価は行ごとの樹種単価ではなく、画面（設定）の立米単価 1 つを全行にかける。
- 歩留まり（ロス率）の入力は無い。余裕と固定の +100mm だけ。
- 合計の元は、設定IDがあればその木材設定IDの明細。無ければ、その製品の「木材設定IDが 0 か空」の明細（`CalcWoodTotalForUnsaved`）。
- 丸めは金額の通貨型変換だけ。行ごとの金額は画面にも表にも持たない。

### 反映の処理（製品台帳の原価へ戻る流れ）

`WoodForm_Apply`（`Evt_木材原価.bas`）:
1. サブフォームの入力途中の行を確定する。
2. 検証: 部位名が空、立米単価が 0 以下、樹種が未選択のどれかなら、メッセージを出して止める。
3. 設定IDが 0 なら新規。`tbl建具台帳_木材設定` へ（建具№、部位名、樹種名、立米単価）を挿入し、（建具№、部位名）で ID を引き直す。同じ製品に同じ部位名が 2 つあると、片方が引かれる。続けて、その製品の木材設定IDが 0 か空の木材明細を、この設定IDへ付け替える。
   設定IDがあれば、その設定の部位名・樹種名・立米単価を上書きする。
4. `ApplyWoodCostToHontai`:
   - 合計 = `CalcWoodTotalBySettingId`（設定IDの明細の材積合計 × 立米単価 × 10000）。
   - 本体名 = `部位名 & "　" & 樹種名 & "　立米" & Format(単価, "0.##") & "万円"`。例は「本体　杉　立米60.万円」。`Format("0.##")` のため、整数の単価でも末尾に小数点が残る。実データも全て「60.万円」の形。
   - 同じ（建具№、木材設定ID）の本体行が無ければ INSERT（本体数量=1、本体単価=本体金額=合計、木材設定ID、並び順=末尾）。あれば UPDATE（本体名・本体単価・本体金額。数量は触らない）。
5. `Df_製品台帳同期.MarkProductChangedAnywhere` で Beaver 同期の対象に印を付ける。
6. 開いている `frm建具台帳` の本体サブフォームを再読込し、「木材原価を製品台帳に反映しました。」を出す。

製品台帳の原価（本体の行）に入るのは「部位ごとに 1 行、数量1、単価＝金額＝材積合計×立米単価」の合計だけで、寸法の明細は原価行に入らない。この行が Beaver の `source='wood_calc'` の行になる。

### 再計算のタイミング

画面内の合計表示は、開いた直後（タイマー）、樹種変更、単価の手入力、数値欄の更新、貼り付け、テンプレート、行削除で `WoodForm_CalcTotal` が走る。製品台帳側の本体の金額は、「反映」ボタンを押したときにしか更新されない。明細や単価を直して反映せずに閉じると、画面の合計と本体の金額がずれる。

### 製品の複製との関係

- 開発版 `src/modules/Mdl建具複製.bas` の `DuplicateTateguRecord` は、親と本体・金物・硝子・労務費をコピーする。本体行の木材設定IDもそのまま写るので、複製先の本体行は元と同じ木材設定を指す。木材設定と木材明細は複製しない。
- 本番版 `src_prod_export/modules/Mdl建具複製.bas` は、さらに木材明細の子コピー（`DuplicateChildren(…, "tbl建具台帳_木材明細")`）を呼ぶ。木材明細は新しい建具№ と元の木材設定IDのままで増える。
- 実データでは、設定 1 の明細が 24 行（建具№ 5637 と 5641 が 12 行ずつ）あり、画面は木材設定IDで明細を引くので 24 行まとめて見え、合計が倍になる。`docs/R-0211_建具台帳の構造とBeaver対応.md:39` の「木材設定・木材明細は別処理」という記述と実装が合っていない。木材設定を複製する `CopyWoodSettingFrom`（`Evt_木材原価.bas:271`）は、複製の処理からは呼ばれていない。

### 実データの不整合

- 木材の本体行 44 行のうち 19 行で、本体金額が「設定の明細の材積合計×単価」の再計算と一致しない。原因は主に 3 つ。
  - 複製で木材設定を共有し、明細が 2 製品分重なった設定（設定 1 は 24 行）の合計が倍になっている。
  - 本体数量を 1 以外にした行（2、3 など）。これは意図した使い方。
  - 反映後に明細を直して再反映していない行（例: 5644 の設定 8・9）。
- 本体の木材行のうち 8 行は金額 0。名前が空の行が 6 行ある。設定だけ作って明細を入れていないか、複製で共有された設定の行。
- 同じ設定を複数の製品が指している例: 設定 1・2・4（5637・5641・5689）、設定 8（5 製品）、設定 15（4 製品）、設定 18（3 製品）。設定の建具№ と明細の建具№ が一致しない明細が 16 行。

## 6. Access の動線で手数が多い・分かりにくい箇所

- 「反映」を押さないと製品の原価に入らず、閉じるときの確認も無い。反映し忘れた入力が 6 製品に残っている。
- 必須入力が部位名・樹種・立米単価の 3 つ。部位名は自由記入で、名前がそのまま原価行の名前になる（本体 / ほんたい / すぎ / hontai と表記が揃わない）。
- 「木材原価追加」は、本体サブフォームで選んでいる行に左右される。新規の設定を作るには木材行以外を選んでおく必要があり、2 つ目の部位を足す操作が分かりにくい。
- 樹種を選ぶと、その製品の全明細（別の部位のものも）の樹種IDが書き換わる。行の樹種IDは計算に使われず、意味が薄い。
- 立米単価の手入力が樹種表と食い違っても、そのまま通る。樹種表に無い単価が実際に使われている。
- 12 行のテンプレートを入れると、使わない行（数 0）が大量に残る。計算には影響しないが、画面が長くなる。
- 計算の前提（長さへ +100mm、余裕は見付と見込みの両方に加算）が、画面のどこにも書かれていない。
- 貼り付けは既存の明細を全削除する。別の部位の明細も消える（製品単位で消すため）。
- 製品複製後に木材設定が共有され、片方を直すともう片方の原価に影響する。
- 部位名が同じ製品内で重複すると、新規の設定IDの特定（建具№ と部位名で検索）を取り違えうる。
- 仕様にある「入力方法の選択ダイアログ」（他の製品からコピー）は作られているが、画面から開けない。

## 7. 読めなかったもの・限界

- FE の accdb（`dodaikun2026.accdb`、`dodaikun2026_dev.accdb`）の中のフォーム定義は、Access を開かないと読めないので読んでいない。フォームは `src/forms` の SaveAsText エクスポートで代用した。探したが無かったもの: `src_prod_export/forms` と `src_export/forms` には木材のフォーム（`frm木材原価計算`・`fsubWoodDetail`・`frmWoodCopyDialog`）が入っていない。`src/forms/frm木材原価計算.frm` には、スクリプトと VBA が使う部品（部位名の入力欄、設定IDの隠し欄、テンプレートと行削除のボタン）が入っていない。実体の FE との差は未確認。
- 位置（Left/Top）は twip の定義値で、実際の見た目（重なりや色）は見ていない。
- BE のリレーションシップ（MSysRelationships）は照会していない。外部キー列に索引が無いことから、制約は無いと推測している。
- 製品名（建具名）だけを見た。得意先に関わる列は読んでいない。
- 調査用のコピー DB と補助スクリプトはスクラッチパッドに置いた（プロジェクトには置いていない）。
